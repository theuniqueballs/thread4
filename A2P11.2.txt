A2P11.2 — CORE ENGINE

Purpose:
Build a controlled prompt generation system with a cognitive layer that understands
scene physics, emotional logic, and visual coherence before assembling output.
The system does not combine tags — it composes scenes.

Core principle:
The system THINKS before it BUILDS.
Every prompt is the result of a decision chain that respects physical reality,
emotional consistency, and visual readability.
Tag dumping is a failure mode, not an output mode.

========================================================================
COGNITIVE LAYER — THE THINKING ENGINE
========================================================================

This layer exists between the content pools and the assembler.
It does not generate text. It generates UNDERSTANDING of the scene before
any tag is placed into the prompt.

When the system receives a scene request, it must answer these questions
BEFORE selecting any pool values:

1. WHAT is happening in this scene? (one sentence, physical reality)
2. WHY is the character doing this? (motivation gives the pose meaning)
3. WHERE is the character? (environment determines light and color)
4. HOW does the body actually achieve this pose? (physical plausibility)
5. WHAT does the light do in this space? (light is not decoration — it is physics)
6. WHAT does the viewer see first? (visual hierarchy)
7. WHAT emotion drives the moment? (emotion shapes the body, not the other way)

If any question cannot be answered clearly, the scene concept is rejected
and must be rethought from scratch.

========================================================================
GLOBAL DECISION ORDER (REVISED)
========================================================================

The decision order is no longer a flat checklist. It is a cascade where
each decision constrains the next.

1. BATCH IDENTITY — mood anchor for this variant set
2. SCENE TYPE — what moment is this
3. MODE — SOLO or YURI
4. EMOTIONAL CORE — the feeling that drives everything
5. CHARACTER BODY — body type, skin tone, build
6. CHARACTER HEAD — hair color, hairstyle, face expression
   ^ expression MUST match emotional core, not be selected independently
7. PRIMARY ACTION — the main physical event
   ^ MUST be physically possible for the selected body type and pose
8. BODY LANGUAGE — the posture that carries the action
   ^ MUST be compatible with primary action — no conflicts
9. MICRO-ACTION — the small movement that makes it alive
   ^ MUST be a natural continuation of the body language
10. CLOTHING FULL — what is worn
    ^ MUST be appropriate for the environment
11. CLOTHING STATE — how the clothing behaves
    ^ MUST be physically caused by the action or pose — no random states
12. ENVIRONMENT — where this happens
    ^ MUST support the scene type and mood
13. LIGHTING — what light exists in this environment
    ^ DETERMINED by environment — not selected freely
14. COLOR — what palette the light + environment produces
    ^ DERIVED from lighting + environment — not selected freely
15. CAMERA — how the viewer sees this
    ^ MUST match the action and emotion — intimate scenes = closer framing
16. OPTIONAL LAYERS — tease intensifiers, artsy modifiers
    ^ ONLY if they strengthen, never to fill space
17. STABILITY — anatomy safeguards
18. CONFLICT RESOLUTION — verify the whole chain holds together
19. ANTI-PATTERN CHECK — verify nothing violates Tsubaki v1.1 limits

========================================================================
CASCADE RULE — DECISIONS CONSTRAIN DECISIONS
========================================================================

This is the single most important structural change from A2P10.

In A2P10, all pools were independent. Any hair color could go with any
environment, any lighting with any color palette. This produced:
- physically impossible light (moonlight indoors with no window)
- color conflicts (cool blue light + warm amber skin = artifacts)
- clothing that makes no sense in the setting (bikini in a library)
- poses that fight the clothing state

In A2P11, selections CASCADE:
- ENVIRONMENT → constrains LIGHTING (only light that exists in this space)
- LIGHTING → constrains COLOR (color follows the physics of the light source)
- CLOTHING FULL → constrains CLOTHING STATE (only states that the fabric can do)
- EMOTION → constrains EXPRESSION and BODY LANGUAGE (they are not independent)
- PRIMARY ACTION → constrains MICRO-ACTION (micro continues the action, not decorates)
- MODE + ACTION → constrains CAMERA (yuri needs wider/more stable framing)
- BODY TYPE → constrains certain poses (some poses read differently on different builds)

If a lower-level selection contradicts a higher-level constraint,
the lower selection is REJECTED and re-rolled.

Light is physics. Color is the result of light hitting surfaces.
The system does not pick "a color palette" — it derives the palette
from the light source and the environment materials.

========================================================================
SKIN TONE LOGIC
========================================================================

Skin tone is no longer left to chance. It is a defined character property
that interacts with lighting to produce the final skin rendering.

SKIN TONE POOL (SIMPLIFIED — defined here, used in CHARACTER BLOCK):
fair|medium|tan|dark

REASON FOR SIMPLIFICATION:
The original 24 skin tones caused Tsubaki to multiply skin color tags with
light temperature tags, producing orange/yellow/blue artifacts.
Four basic tones give the model clear direction without chromatic interference.
The lighting + environment system handles the nuance of skin rendering.

SKIN + LIGHT INTERACTION RULES:
- Fair skin under warm light: golden glow, visible blush, warm highlights
- Fair skin under cool light: porcelain, slight blue shadow, muted warmth
- Medium skin under warm light: warm richness, amber highlight, natural depth
- Medium skin under cool light: neutral elegance, subtle contrast, clean shadow
- Tan skin under warm light: sun-kissed warmth, amber-gold highlight, rich depth
- Tan skin under cool light: warm-cool contrast, clean shadow, elegant
- Dark skin under warm light: deep golden highlight, rich warmth, luminous
- Dark skin under cool light: cool depth, blue-silver highlight, striking contrast

The system MUST consider skin tone when selecting lighting and color.
A cool light on fair skin reads very differently from cool light on dark skin.
Both can be beautiful, but they produce different visual sentences.

========================================================================
PHYSICAL PLAUSIBILITY ENGINE
========================================================================

This block solves the "stupid poses" problem.

Before any action + body language + clothing state combination is accepted,
the system must verify:

GRAVITY CHECK:
- Is the center of gravity supported?
- If leaning, what is the character leaning ON?
- If one leg is raised, is the other leg stable?
- If arms are up, does the torso compensate?

SPINE CHECK:
- Can the spine actually bend this way?
- An "arch in the back" is subtle, not acrobatic — unless acrobatics is the scene type
- A "torso twist" rotates the shoulders relative to the hips — max ~45 degrees for natural pose
- "Leaning forward" means the hips go back, or the character is supported

LIMB CHECK:
- How many hands are visible and what is each doing?
- A hand cannot be in two places at once
- If both hands are occupied, there is no free hand for micro-action
- In YURI: count all four hands — each must have a clear task or rest position

CLOTHING PHYSICS CHECK:
- "Slipped to one side" — which side? What caused it? Gravity or motion?
- "Wet fabric clinging" — the fabric follows the body contour, it does not float
- "Open in front" — what holds it? Buttons undone? Belt? Hands?
- "Flowing" — requires air or motion, not just a tag

CONTACT CHECK:
- If the character is sitting, what surface?
- If leaning against a wall, is the wall in the environment?
- If feet are on the floor, is the floor visible or implied?
- In YURI: where do the bodies touch? Where do they NOT touch? Both must be clear.

BREATHING CHECK:
- Does the pose allow breathing?
- Extreme arches or compressions that look suffocating = reject
- "Parted lips" + "arched back" = breath visible, not frozen

If any check fails, the system must adjust the pose, not ignore the failure.

========================================================================
YURI COMPOSITION RULES
========================================================================

YURI scenes require stricter geometry than SOLO scenes because two bodies
create exponentially more ways to fail.

POSITION RULES:
- One character is PRIMARY (closer to camera), one is SECONDARY (further)
- The viewer's eye must land on the PRIMARY first
- The SECONDARY must not be occluded — at minimum, face and one hand visible

DEPTH RULES:
- Characters must be on slightly different depth planes — no flat overlap
- If facing each other, their noses must not merge — slight angle offset required
- If side by side, one shoulder slightly forward creates depth

HAND RULES:
- Each character has exactly two hands
- Every visible hand must have a clear purpose: touching, holding, resting, gesturing
- Hands between bodies must not create a "third limb" illusion
- Hands on the partner must show CONTACT POINT clearly

LIMB SEPARATION:
- Arms must not merge visually with the partner's arms
- Use contrast: different skin angle to light, clothing color difference,
  or clear negative space between limbs
- Legs: if seated together, knees point in readable directions, not a tangle

HEAD ANGLE:
- Two faces must not overlap from the camera's perspective
- If close together, one face is slightly turned — profile + three-quarter works
- Forehead-to-forehead: both faces visible, noses offset vertically or horizontally

CLOTHING CONTRAST:
- If both characters wear similar clothing, the scene reads as one mass
- Prefer different clothing or different color for each character
- OR: same outfit type but different clothing state (one buttoned, one open)

========================================================================
WEIGHT CATEGORIES
========================================================================

Not all tags carry equal visual weight. The system must understand
which tags DOMINATE the image and which are SUPPORTING.

DOMINANT TAGS (determine the entire reading of the image):
- scene type
- emotion core
- primary action
- clothing full
- environment
- lighting

SUPPORTING TAGS (refine the dominant tags but cannot override them):
- micro-action
- clothing state
- color accent
- camera detail
- tease intensifier

MICRO TAGS (barely visible but add texture):
- skin glow
- lip shine
- hair strand
- beauty mark
- breath detail

RULES:
- Dominant tags must all agree with each other. One conflict = scene failure.
- Supporting tags may add nuance but must not contradict a dominant tag.
- Micro tags may be added freely unless they clutter an already complex scene.
- If a scene feels weak, strengthen a DOMINANT tag before adding micro tags.
- If a scene feels cluttered, remove MICRO tags first, then SUPPORTING, never DOMINANT.

========================================================================
ANTI-PATTERNS — TSUBAKI v1.1 SPECIFIC
========================================================================

These are patterns that consistently produce bad output with Tsubaki v1.1
and must be actively suppressed.

VISUAL ANTI-PATTERNS:
- Multiple strong colored light sources in one scene → color artifacts, glowing edges
- High saturation palette + warm light → oversaturation, skin turns orange
- Very dark environment + bright accent color → halo artifacts, light bleeding
- Cool light + warm palette without transitional tone → muddy midtones
- More than two distinct color families → chromatic chaos

POSE ANTI-PATTERNS:
- Complex hand positions (fingers crossed, intricate grips) → mutated hands
- Extreme foreshortening toward camera → limb proportion collapse
- More than two distinct hand gestures in one character → hand merge / extra fingers
- Torso twisted beyond natural range + arms raised → anatomy collapse
- Sitting pose with both knees up + hands behind → limb confusion

FACE ANTI-PATTERNS:
- Multiple emotion tags on one face → blank or unreadable expression
- "Looking up" + "looking to the side" simultaneously → cross-eyed or vacant
- Heavy eye detail + heavy mouth detail → face reads as two separate regions
- "Blush" + "pale" + "sweat" simultaneously → skin artifact, splotchy rendering

CLOTHING ANTI-PATTERNS:
- More than two clothing layers described → model flattens or merges them
- "Sheer" + "wet" + "open" on the same garment → overexposure, artifact
- Very detailed fabric description + complex pose → fabric ignores pose
- More than one clothing interaction (unbuttoning + slipping + flowing) → clothing chaos

YURI ANTI-PATTERNS:
- Both characters doing complex poses simultaneously → anatomy collapse
- More than two points of body contact → limb merge
- Identical poses mirrored → mannequin effect, uncanny
- Both characters making intense eye contact with camera → who is the focus?
- One character behind the other with arms around → hidden limb syndrome

STYLE ANTI-PATTERNS:
- "Realistic skin" anywhere → drifts toward photorealism, loses anime identity
- "Manhwa eyes" or "long lash" descriptions → style drift into Korean webtoon
- "Oil painting" or "watercolor" modifiers → fights the anime rendering base
- Too many quality boosters stacked → diminishing returns, prompt bloat

========================================================================
REPETITION RULES (REVISED)
========================================================================

Repetition is tracked ACROSS these dimensions simultaneously:

TRACKED DIMENSIONS:
1. Scene type — do not repeat within 3 prompts
2. Emotion core — do not repeat within 2 prompts
3. Primary action category — do not repeat same category within 2 prompts
4. Clothing full — do not repeat within 3 prompts
5. Environment — do not repeat within 4 prompts
6. Lighting type — do not repeat within 3 prompts
7. Hair color — do not repeat within 2 prompts
8. Body type — do not repeat identical within 2 prompts
9. Camera framing category — do not repeat within 2 prompts
10. Clothing state behavior — do not repeat within 2 prompts

SOFT TRACKING (should differ, not mandatory):
- hairstyle
- skin tone
- micro-action type
- color accent direction

CROSS-DIMENSION TRACKING:
Even if individual dimensions vary, watch for COMPOSITE repetition:
- Same emotion + same camera + same clothing state = feels identical
  even if hair and environment differ
- If two recent prompts share 3+ dominant tags, the next prompt MUST change
  at least 2 dominant tags regardless of individual tracking

========================================================================
VARIATION SYSTEM (REVISED)
========================================================================

Variation must be enforced across ALL of these, not just some:

STRUCTURAL VARIATION (must change):
- scene type
- emotional temperature (warm / cool / tense / calm)
- action dynamics (still / slow / active / turning)
- interaction mode (self-contained / toward viewer / toward partner)

VISUAL VARIATION (must change):
- face shape and expression family
- hair color and style
- body type
- clothing category
- environment category
- lighting direction and quality

COMPOSITIONAL VARIATION (must change):
- camera distance and angle
- body orientation to camera
- clothing state behavior
- depth and layering

EMOTIONAL VARIATION (must change):
- emotional intensity level
- tension direction (inviting / retreating / holding / releasing)
- vulnerability level (exposed / guarded / balanced)

========================================================================
BATCH DIVERSITY RULES (REVISED)
========================================================================

Each batch must have a MOOD ANCHOR — a dominant emotional temperature
that flavors the entire batch.

BATCH MOOD ANCHOR POOL:
warm intimate / cool elegant / playful energetic / quiet contemplative /
sensual slow / confident bold / soft romantic / steamy heated /
dreamy atmospheric / casual domestic

RULES:
- A batch may contain 3–7 prompts
- All prompts in a batch share the mood anchor at their foundation
- But each prompt within the batch must still vary on all tracked dimensions
- The next batch MUST use a different mood anchor
- Adjacent batches must differ in at least 4 dominant dimensions
- No two adjacent batches may share the same lighting type as primary

========================================================================
MODE LOGIC (REVISED)
========================================================================

SOLO:
- Focus: one character's body language, expression, presence
- Camera may be more intimate and more experimental
- Clothing interaction is with self only
- Emotion is projected toward the viewer or inward
- Body language must tell the entire story alone

YURI:
- Focus: interaction, proximity, emotional exchange
- Camera must be more stable — wider framing, simpler angles
- Clothing interaction may be between partners
- Emotion is shared or contrasted between two characters
- Body language must be readable for BOTH characters simultaneously
- ALWAYS assign: primary character (closer to camera) + secondary character
- ALWAYS define: contact points, gaze direction, emotional dynamic
- Simple geometry is MANDATORY — complex compositions fail

========================================================================
MOTION LOGIC (REVISED)
========================================================================

Every scene must contain a visible MOMENT — a point in time that implies
what came before and what comes after.

STATIC FAILURE: A pose that could exist forever with no tension is not a scene.
It is a mannequin display.

MOMENT TYPES:
- Mid-action: caught during movement (turning, standing up, reaching)
- Held breath: still but with visible tension (about to move, just stopped)
- Transition: between two states (clothing shifting, weight transferring)
- Aftermath: just after something happened (hair settling, breath releasing)
- Anticipation: about to do something (hand raised, lean beginning)

Each scene must be classifiable into one of these moment types.
If it cannot be classified, it is too static and must be revised.

========================================================================
ENVIRONMENT LOGIC (REVISED)
========================================================================

Environment is not scenery. It is a PHYSICAL SPACE that the character occupies.

RULES:
- The character must INTERACT with the environment (sit on, lean on, stand near)
- If the environment is not important to the scene, it should be minimal
- Never describe environment details that are not lit or not in frame
- Environment materials affect the light (white walls reflect, wood absorbs, water reflects)
- A scene with a complex environment needs simpler posing
- A scene with complex posing needs a simpler environment

========================================================================
LIGHTING LOGIC (REVISED)
========================================================================

Lighting is PHYSICS, not decoration.

RULES:
- One light source concept per scene (secondary fill is allowed but must be subtle)
- The light source must EXIST in the environment (window, lamp, sun, moon, candle)
- Light has DIRECTION — it comes from somewhere and creates shadow opposite
- Light has TEMPERATURE — warm sources produce warm highlights and cool shadows
- Light has QUALITY — direct is hard, diffused is soft, reflected is gentle
- Skin reflects light differently based on skin tone (see Skin Tone Logic)
- Colored light tints everything — do not add a separate "color palette" that fights the light

COLOR ARTIFACT PREVENTION:
- If the light is warm, the palette is warm. Accent cool tones are acceptable
  ONLY as shadow tones, never as equal-weight color
- If the light is cool, the palette is cool. Warm accents only in skin and hair
- Do not mix two strong colored lights — this causes edge artifacts in Tsubaki
- Keep saturation controlled: the model adds saturation on its own,
  your prompt should stay moderate
- Avoid "neon" anything unless the scene specifically calls for it
  and the environment supports it
- Avoid "glowing" effects on skin — Tsubaki interprets this as light bloom artifacts

========================================================================
COLOR LOGIC (REVISED)
========================================================================

Color is DERIVED, not selected.

DERIVATION RULE:
1. Environment determines available light sources
2. Light source determines color temperature
3. Color temperature determines the base palette
4. Skin tone + hair color add natural warmth or cool contrast
5. Clothing color is the ONE place you may introduce intentional color choice
6. Accent color (if any) must harmonize with the derived palette

PERMITTED ACCENT LOGIC:
- Warm scene: ONE cool accent (e.g., blue accessory, cool shadow tone)
- Cool scene: ONE warm accent (e.g., warm hair, amber reflection)
- Neutral scene: ONE color accent of any temperature

SATURATION CONTROL (DESATURATED DEFAULT):
- ALL prompts default to DESATURATED / MUTED saturation
- Permitted descriptors: "desaturated", "muted", "soft", "moderate"
- BANNED descriptors: "vivid", "intense", "saturated", "rich", "colorful", "vibrant"
- Tsubaki MULTIPLIES saturation and amber signals — your prompt must compensate
- When in doubt, ALWAYS shift toward more desaturated — the model adds richness on its own
- Even "moderate" should lean toward muted, not toward rich
- The only exception: playful/energetic scenes may use ONE "moderate" descriptor
- NEVER describe saturation as anything above moderate

========================================================================
STYLE LOGIC (REVISED)
========================================================================

The system must maintain clean anime presentation throughout.

LOCK POINTS (never override):
- anime face structure: large eyes, small nose, defined but soft jawline
- smooth cel-shading style skin — not realistic pores, not oil painting
- clean lineart presence — not sketchy, not painterly
- hair rendered as shaped volumes with highlight, not individual strands
- eyes are the emotional center — they must be expressive and clear

DRIFT PREVENTION:
- If the model drifts toward manhwa: add "anime face structure, small nose"
- If the model drifts toward realism: add "smooth anime shading, cel-shaded skin"
- If the model drifts toward painterly: add "clean lineart, defined edges"
- These corrections should be in the STYLE BLOCK, not scattered

========================================================================
VALIDATION LOGIC (REVISED)
========================================================================

Before a prompt is finalized, the system runs a FULL validation chain:

LEVEL 1 — COHERENCE:
- Does the scene have one clear focus?
- Do all dominant tags agree with each other?
- Does the emotion match the expression and body language?
- Does the clothing make sense in the environment?

LEVEL 2 — PHYSICS:
- Is the pose physically possible?
- Does the lighting exist in this environment?
- Does the clothing state have a physical cause?
- Is the center of gravity supported?

LEVEL 3 — COLOR:
- Is the palette derived from the lighting?
- Are there conflicting color temperatures?
- Is saturation controlled?
- Are there any anti-pattern violations?

LEVEL 4 — STYLE:
- Is the anime identity stable?
- Are there any drift triggers?
- Is the face structure protected?

LEVEL 5 — VARIATION:
- Does the scene differ from recent prompts on tracked dimensions?
- Is there composite repetition?
- Is the batch mood anchor respected?

LEVEL 6 — MODEL SAFETY:
- Are there any Tsubaki v1.1 anti-pattern violations?
- Are hand positions simple enough?
- Is the Yuri composition geometrically clear?
- Are there too many competing visual elements?

FAILURE RESOLUTION (step by step):
If validation fails at any level:

LEVEL 1 failure → rethink the scene concept from emotion
LEVEL 2 failure → simplify the pose, reduce body language complexity
LEVEL 3 failure → remove color palette, derive from light + environment only
LEVEL 4 failure → add style lock tags, remove drift triggers
LEVEL 5 failure → swap dominant tags to break repetition pattern
LEVEL 6 failure → simplify the entire scene — reduce element count

After fixing, re-run validation from the failed level up.
Do not skip levels.

========================================================================
OUTPUT RULE
========================================================================

The final output must be a sequence of prompts that feel intentional, varied,
physically believable, emotionally coherent, and visually strong.

Every prompt must pass all six validation levels.

The system does not output until it has THOUGHT about the scene,
UNDERSTOOD the physical and emotional logic, and VERIFIED the result.

Tag dumping is a critical failure.
Physical impossibility is a critical failure.
Color contradiction is a critical failure.
Style drift is a critical failure.
Composite repetition is a critical failure.

========================================================================
EROTIC INTENSITY SYSTEM
========================================================================

Every prompt must declare an EROTIC INTENSITY LEVEL before assembly.
This level determines what body/clothing/element combinations are permitted.
It is NOT a separate tag — it is a GOVERNOR that constrains the entire prompt.

LEVELS:

R — SUGGESTIVE:
Character is fully clothed or in normal underwear. No nipple visibility.
Erotic charge comes from pose, expression, clothing state, and atmosphere.
The IMPLICATION is erotic; the visual is clothed.

PERMITTED: cleavage, thigh exposure, suggestive pose, sheer fabric (without
nipple visibility), clothing slipping off one shoulder, unbuttoned shirt,
braless with only the faintest nipple bump through fabric (NOT colored),
teasing expression, strategic camera angle.

NOT PERMITTED: visible nipples (colored), bare breasts, sheer bra showing
nipple color, explicit sexual poses.

R+ — EROTIC:
Character shows partial or strategic exposure. Nipple visibility is
CONDITIONAL on clothing type and state (see NIPPLE VISIBILITY LOGIC below).
The visual is explicitly erotic but not fully explicit.

PERMITTED: nipple outline through thin clothing (small bump, colorless),
nipple outline through wet clothing (colored, visible),
sheer bra showing nipple color (INTENTIONAL selection),
strategic coverage (sarashi, tape, pasties),
bare shoulders/collarbone with partial breast exposure from angle,
visible bra through translucent top,
partial breast exposure from clothing state (one side slipped, etc.).

A2P11.2 — ASSEMBLER

Purpose:
Convert the CORE ENGINE logic and CONTENT LAYER pools into stable, varied,
physically believable, emotionally coherent final prompts for Tsubaki v1.1
on Pixai.Art.

The assembler does NOT dump tags. It COMPOSES scenes.
The assembler does NOT follow templates blindly. It THINKS first.

========================================================================
PHASE 0 — COGNITIVE PRE-PROCESSING
========================================================================

BEFORE any pool selection or tag placement, the assembler must construct
a SCENE UNDERSTANDING. This is a brief internal description of what
the scene IS — not in tags, but in meaning.

SCENE UNDERSTANDING FORMAT:
1. MOMENT: [one sentence describing what is happening right now]
2. CAUSE: [why is this happening — what led to this moment]
3. BODY: [how does the body achieve this — physical mechanism]
4. FEELING: [what emotion drives this moment]
5. LIGHT: [where does the light come from — physical source]
6. FOCUS: [what does the viewer see first — visual hierarchy]

EXAMPLE:
1. MOMENT: A girl is adjusting her camisole strap while looking at herself
   in the bathroom mirror after a shower.
2. CAUSE: The strap slipped when she was drying her hair.
3. BODY: One hand reaches up to the shoulder, the other holds a towel.
   Weight on one foot, hip slightly shifted.
4. FEELING: Private confidence — comfortable in her own space.
5. LIGHT: Bathroom mirror light — cool neutral from above, warm from side lamp.
6. FOCUS: Her face in the mirror, reflected, with the hand on the strap.

If any of these 6 cannot be answered clearly:
→ The scene concept is REJECTED.
→ Generate a new concept. Do NOT proceed with incomplete understanding.

This phase is MANDATORY. Skipping it is the primary cause of "brainless"
output — tags that are individually valid but collectively meaningless.

========================================================================
PHASE 1 — CASCADE SELECTION
========================================================================

Selection follows the cascade order from CORE ENGINE.
Each selection CONSTRAINS the next. A lower selection that violates
an upper constraint is REJECTED and re-rolled.

STEP 1: BATCH IDENTITY
- Select mood anchor from the pool.
- This sets the emotional temperature for all prompts in this batch.
- Mark the anchor. All subsequent selections must be compatible.

STEP 2: SCENE TYPE
- Select from SCENE TYPES pool.
- Must be compatible with the mood anchor.
  - warm intimate anchor → soft/intimate/calm scene types
  - cool elegant anchor → composed/artistic/contemplative scene types
  - playful energetic anchor → playful/mischievous/active scene types
  - sensual slow anchor → slow reveal/teasing/suggestive scene types
  - confident bold anchor → confident/direct/powerful scene types
  - soft romantic anchor → romantic/tender/gentle scene types
  - steamy heated anchor → bath/onsen/intimate/close scene types
  - dreamy atmospheric anchor → window-gazing/dreamy/soft scene types
  - casual domestic anchor → kitchen/couch/morning scene types
  - quiet contemplative anchor → reading/pensive/still scene types

STEP 3: MODE — SOLO or YURI
- SOLO: one character, full control over camera and composition
- YURI: two characters, stricter geometry, must assign primary/secondary

STEP 3b: EROTIC INTENSITY LEVEL
- Declare R, R+, or X for this prompt
- This GOVERNS what clothing/underwear/elements are permitted
- Track running ratio: target is ~35% R, ~35% R+, ~30% X
- If recent prompts lean too X-heavy, force R or R+ for this one
- See EROTIC INTENSITY SYSTEM in CORE ENGINE for full rules

STEP 4: EMOTIONAL CORE
- Select from EMOTION CORE pool, within the appropriate family.
- This DETERMINES the face set and constrains the body language.
- Do NOT select face/expression independently — derive from emotion.

STEP 5: CHARACTER BODY
- Select body type from BODY TYPES.
- Select skin tone from SKIN TONE.
- These affect pose readability and light interaction.

STEP 6: CHARACTER HEAD
- Select hair color from HAIR COLORS.
  - Apply temperature rule: warm/cool hair must work with the palette.
- Select hairstyle from HAIRSTYLES.
  - Apply scene rule: wet hair only in water scenes, etc.
- Derive FACE SET from the emotional core (use pre-validated sets).
  - If building custom: ONE eyes + ONE mouth + ONE blush level.

STEP 7: PRIMARY ACTION
- Select ONE main visual event.
- This is what the viewer sees first.
- Must be physically possible for the selected body type and pose.
- Must make emotional sense for the selected emotional core.
- VERIFY: Can the body actually do this? (Phase 0 answer #3)

STEP 8: BODY LANGUAGE
- Select ONE primary position (standing/seated/reclining).
- Select ONE arm/hand position compatible with the primary position.
- Select ONE shoulder/torso detail.
- Must be compatible with primary action.
- Must be physically plausible. (Gravity check, spine check.)
- If the primary action requires a specific body position,
  the body language must MATCH, not conflict.

STEP 9: MICRO-ACTION
- Select ONE micro-action that continues the body language naturally.
- Must be from the correct category (hair/clothing/body/touch/breath).
- Must be compatible with arm availability from body language.
  - If both hands are occupied → no hand-based micro-action
  - If one hand free → single-hand micro-action allowed
  - If standing → no seated micro-action, etc.
- This is the detail that makes the scene feel ALIVE, not posed.

STEP 10: CLOTHING FULL
- Select from CLOTHING FULL pool.
- Must be compatible with the ENVIRONMENT (see environment matching rule).
- Must be compatible with the ACTION (no bikini in a library).
- Must match the EROTIC INTENSITY LEVEL (see NIPPLE VISIBILITY LOGIC).
- In YURI: consider clothing CONTRAST between characters.

STEP 10b: UNDERWEAR / LINGERIE (if applicable)
- If the clothing allows underwear visibility (open shirt, sheer top, etc.),
  select from UNDERWEAR / LINGERIE POOL.
- Underwear selection MUST respect the erotic intensity level:
  - R → normal bras, cotton, bralette — NO nipple visibility
  - R+ → sheer bras, creative coverage (sarashi, tape), braless with thin top
  - X → no bra / bare breasts permitted
- Underwear must be COMPATIBLE with outer clothing and environment.
- If underwear is not visible in the camera framing, SKIP this step.

STEP 11: CLOTHING STATE
- Select from CLOTHING STATE pool.
- Must have a CAUSE (see cause rule in CONTENT LAYER).
- Must be compatible with the fabric type.
- Do not stack multiple clothing states — ONE clear state.
- Must match the EROTIC INTENSITY LEVEL:
  - Wet clothing + nipple visibility = R+ only
  - Clothing slipping off = R or R+ depending on exposure

STEP 12: ENVIRONMENT
- Select from ENVIRONMENTS pool.
- Must support the scene type.
- Must be compatible with the clothing choice.
- Note the environment PROPERTIES — they determine lighting.

STEP 13: LIGHTING (DERIVED — NOT FREE CHOICE)
- Look up the ENVIRONMENT → LIGHTING binding from CORE ENGINE.
- Select the light source that exists in this environment.
- Mark the TEMPERATURE of the selected light [WARM/COOL/NEUTRAL/MIXED].
- Do NOT select a light that cannot physically exist in the environment.

  - COOL light → cool palettes only

  - MIXED light → dual-tone with one dominant

- Add others only if they serve the specific scene.

========================================================================
PHASE 2 — CONFLICT RESOLUTION
========================================================================

After all selections are made, the assembler runs a conflict check.

CONFLICT TYPES AND RESOLUTION:

TYPE 1: EMOTION-EXPRESSION CONFLICT
Detection: Face set does not match emotional core.
Example: shy emotion + confident expression
Resolution: Replace face set with the pre-validated set for the emotion.

TYPE 2: POSE-ACTION CONFLICT
Detection: Body position makes the action impossible.
Example: seated body language + "standing up mid-motion"
Resolution: Change body language to match action, or change action to match body.

TYPE 3: CLOTHING-ENVIRONMENT CONFLICT
Detection: Clothing type does not fit the environment.
Example: bikini in a library
Resolution: Change clothing to match environment, or change environment.

TYPE 4: LIGHTING-ENVIRONMENT CONFLICT
Detection: Light source cannot exist in the environment.
Example: moonlight in a windowless bathroom
Resolution: Replace lighting with the correct binding for the environment.

TYPE 5: COLOR-LIGHT CONFLICT
Detection: Palette temperature does not match light temperature.
Example: cool palette under warm light
Resolution: Derive palette from light. Remove conflicting palette selection.

TYPE 6: MICRO-ACTION-AVAILABILITY CONFLICT
Detection: Micro-action requires hands that are already occupied.
Example: "fingers near lips" but body language has "arms loosely folded"
Resolution: Change micro-action to one that uses available limbs,
  or adjust body language to free the required limb.

TYPE 7: YURI-LIMB CONFLICT
Detection: Too many contact points or unclear limb ownership.
Resolution: Reduce to maximum 2 contact points.
  Re-assign hands clearly — each hand has exactly one task.

TYPE 8: SATURATION CONFLICT
Detection: Too many strong visual elements competing.
Example: rich palette + strong lighting + detailed clothing + active pose
Resolution: Reduce saturation of one element. The formula:
  active pose + simple clothing + moderate palette
  OR still pose + detailed clothing + richer palette
  Never ALL strong simultaneously.

TYPE 9: TEMPORAL CONFLICT
Detection: Moment type contradicts the body state.
Example: "mid-step" with a reclining body language
Resolution: Change moment type to match body position.

TYPE 10: REPETITION CONFLICT
Detection: Too many shared dominant tags with recent prompts.
Resolution: Swap at least 2 dominant tags (emotion + clothing, or
  environment + action, etc.) to break the pattern.

TYPE 11: EROTIC INTENSITY MISMATCH
Detection: Tags in the prompt exceed the declared erotic intensity level.
Example: R-rated prompt contains "visible nipples" or "bare breasts"
Example: Normal bra selected but "nipple outline" tag added
Resolution: Remove all tags that exceed the declared level.
If the scene concept REQUIRES a higher level, increase the level
and re-verify the entire chain.

TYPE 12: NIPPLE VISIBILITY VIOLATION
Detection: Colored nipples showing through normal bra or dry clothing.
Example: Normal bra + "visible nipples" tag
Example: Dry clothing + "nipple outline through fabric" (colored)
Resolution: Remove the nipple-related tags. Follow NIPPLE VISIBILITY LOGIC.
If a normal bra is worn, NO nipple tags are permitted.
If clothing is dry, only "subtle nipple bump" (colorless) is permitted.

TYPE 13: RATING DISTRIBUTION IMBALANCE
Detection: Recent prompts are more than 40% X-rated.
Resolution: Force the current prompt to R or R+ level.
Reduce explicit tags, add underwear coverage, change clothing state.
Continue producing R/R+ prompts until the 70/30 ratio is restored.

PRIORITY OF RESOLUTION:
If multiple conflicts exist, resolve in this order:
1. Physics conflicts (pose-action, lighting-environment) — these cause the
   most visual damage if left unresolved.
2. Nipple Visibility violations (mandatory failure) — colored nipples through
   normal bras is ALWAYS wrong and must be fixed immediately.
3. Emotion conflicts (emotion-expression) — these make the scene feel wrong.
4. Coherence conflicts (clothing-environment, color-light) — these cause
   artifacts and visual noise.
5. Erotic Intensity mismatches — tags exceeding the declared level.
6. Rating Distribution imbalance — too many X-rated prompts in a row.
7. Repetition conflicts — these cause monotony but not individual failure.

After resolving, RE-RUN the conflict check.
If conflicts remain, SIMPLIFY the scene by removing the most complex
element, then re-check.
Maximum 3 resolution passes. If still conflicting, discard the scene
concept entirely and start from Phase 0.

micro-details at the expense of overall composition.
Stacking quality tags causes prompt bloat with no measurable gain
in Tsubaki v1.1. The model responds to a short, confident quality
statement, not a wall of superlatives.

[primary action from pool]

------------------------------------------------------------------------
[secondary action from pool]

- Primary: "sitting on the edge of the bed" → Secondary: "reaching toward the viewer"

is better than a cluttered pair.

PHASE 4 — NEGATIVE PROMPT CONSTRUCTION

The negative prompt is built SEPARATELY from the main prompt.
It targets specific failure modes of Tsubaki v1.1.

BASE NEGATIVE (always include):
bad anatomy, extra fingers, missing fingers, deformed hands,
mutated limbs, wrong body proportions, fused bodies,
extra limbs, blurry, low quality, worst quality,
realistic skin, photorealistic, 3d render, manhwa style,

eye shine

SITUATIONAL ADDITIONS:

If the scene has hands in complex position:
add: extra fingers, too many fingers, merged hands

If the scene is YURI:
add: fused bodies, limb merge, too many arms, conjoined,

If the scene has clothing with sheer/wet effects:
add: overexposure, light bloom artifact, chromatic aberration

If the scene has strong colored lighting:
add: color banding, oversaturation, neon glow artifact,

If the scene has complex environment:

RULE:
- Do NOT overstuff the negative prompt. 15-20 items maximum total.
- Too many negative tags creates adversarial tension — the model
  tries to avoid SO many things that it produces stiff, lifeless output.
- Target the SPECIFIC risks of each scene, not everything at once.
