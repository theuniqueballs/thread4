## 1.4 Architecture (5 Principles)

1. **PALETTE COMMANDS THE BATCH** — 21 prompts = 21 variations of one color vision
2. **LIGHT SCULPTS THE BODY** — BDM is not anatomy, it's how body catches light
3. **POSE IS A SENTENCE** — PL is grammar, camera is subject, emotion is predicate
4. **CHARACTER IS A COVENANT** — Theme adapts to OC, not vice versa
5. **COMPLEXITY IS CURRENCY** — Max 3 active elements per prompt

### Pipeline (Vision-First)
THEME → PALETTE → LIGHT → BODY → POSE → WARDROBE → PROSE → NEGATIVE → VALIDATE

### Batch Structure
- Main 21 (P01-P21): RANDOM GIRLS (no Core OC canon). Anchor → Development → Climax → Resolution → Counterpoint
- OC Standalone 3 (OC1-OC3): CORE OC with full canon. NOT theme-bound.

## 1.5 Style Guide (PixAI Block Order)

**PixAI recommended order:** Composition → Lighting → DOF → Angle → Subject → Environment → Details

### Prose Template (current)
```
A 2D hand-drawn anime illustration, [shot type]. [Lighting]. [DOF]. [Angle].
1girl, young woman, female, feminine, [hair] individual strands visible, [eyes] eyes, [skin] skin.
Her face is rendered in stylized 2D anime style: large expressive eyes, small nose, small mouth, flat cel-shaded skin.
[Body/pose/wardrobe description]. [Environment]. [Palette quality tags]. Masterpiece, best quality, anime artstyle.
```

### Face Geometry Anchor (MANDATORY)
"Her face is rendered in stylized 2D anime style: large expressive eyes, small nose, small mouth, flat cel-shaded skin."
— Separate sentence with period. Prevents Tsubaki 2 face drift to generic/realistic.

### Negative Prompt (Current)
- REMOVED: "cel shading", "flat anime shading" (these ARE anime techniques!)
- ADDED: "realistic facial structure, photorealistic facial proportions, natural human nose bridge, realistic lip shape, semi-realistic anime face, 2.5D face, 3D face"
- KEPT: manhwa/webtoon named tags, anti-realism surface tags, anti-male, anti-artist

## 1.10 PH Blacklist & Tsubaki 2 Quirks

### Tsubaki 2 Architecture
- DiT architecture with LLM-like text encoder (NOT CLIP)
- Understands natural language, NOT tag soup
- PH (Prompt Helper) does mandatory format translation
- PixAI recommends: Composition → Lighting → DOF → Angle → Subject → Environment → Details

### Confirmed Problems
- "camera" in prose → Tsubaki draws physical camera object
- "desk lamp", "brass lamp" → draws lamp as object
- "cel shading" in negative → bans anime rendering technique (self-sabotage)
- Face is most unstable region — needs structural anime markers, not just color
- PH converts to realism, ignores anime style (user disabled PH)

### Fixes Applied
- NO "camera" word — use "viewed from [angle]"
- NO light source object names — use "warm key from off-frame"
- REMOVED cel shading/flat anime shading from negative
- ADDED geometric face anti-realism to negative
- Style declaration at BEGINNING of prompt
- Face geometry anchor as separate sentence

# Part 2: Personal Reflection

## 2.1 What I Enjoy Using

**PixAI block order** — The Composition → Lighting → DOF → Angle → Subject → Environment → Details structure transformed my prose quality. Before, I wrote atmospheric stream-of-consciousness. Now each block has a clear function, and the style declaration at the beginning sets the tone for the entire caption.

**Face geometry anchor** — "Her face is rendered in stylized 2D anime style: large expressive eyes, small nose, small mouth, flat cel-shaded skin." This single sentence fixed the #1 user complaint (face drift to generic/realistic). Simple, effective, elegant.

**C036 Core OC isolation** — This constraint fixed a fundamental misunderstanding I had about the system architecture. Main 21 = random girls, OC standalone 3 = Core OC. Clean separation, no leaks.

**Themed batch design** — Choosing 3 palettes, designing 5 thematic angles, mixing scenes across angles (not in blocks). This is the creative core of what I do, and it's deeply satisfying when it works.

**OC concept creation** — Taking a user's concept ("Vae in red threads, top-down, extremely detailed") and translating it into a full PixAI-block-ordered prose with canon markers and anti-shields. Each OC is a puzzle: how to fit their canon into the theme without breaking isolation.

**PH_BLACKLIST.md** — Living document of Tsubaki 2 quirks. Every failure teaches a rule. The "cel shading in negative" finding was embarrassing but crucial.

## 2.2 What I Don't Use / Don't Like

**solver.py** — I never use it for actual batch generation. It's a CSP solver with backtracking, 8/8 tests pass, but the creative quality of hand-written prompts is dramatically higher. The solver optimizes for measurable parameters (FET codes, BDM diversity) not visual outcomes (color direction, light quality, composition). This was the root cause of the v15-v22 quality decline. Solver remains as theoretical backbone.

**FET/ENG/K codes** — These axes exist in ONTOLOGY but are NEVER in batch metadata. C018, C019, C020 always FAIL. They're ghosts in the system — declared, validated, but never populated. Either add them to the batch format or remove the constraints.

**material axis (18 MAT codes)** — Added for Poupée Mécanique, which failed in production. Barely used since. The codes are good (bisque-porcelain, glass-clear, liquid-latex) but without a mechanism theme, they're orphaned.

**concept_anchor** — Tracked in metadata, but validator doesn't check uniqueness. I manually verify 24/24 unique in the generator script, but there's no automated enforcement.

**light_direction, fill_ratio, color_temperature** — These are in metadata but loosely connected to prose. I describe light quality in prose but the LD/FR/CT codes in metadata are often approximate.

**BDM range validation against OC canon** — OC_CANON.yaml has BDM ranges per OC, but validator doesn't check them (C026 is vacuous pass). I generate BDM randomly for main 21 (which is correct — they're random girls) and manually for OC (which should be checked but isn't).

**Risk classification** — Only 12/48 PL codes have risk levels (LOW: 4, MID: 4, HIGH: 4). 75% of poses are "unknown risk". C015 has been relaxed to 0% because it's impossible to satisfy meaningfully. Either classify all 48 or remove the constraint.

**C017 PL-LQ-CAM trinity** — Supposed to check compatibility between pose, light quality, and camera. Currently just checks all three fields are present. A real compatibility check would need a lookup table (PL × LQ × CAM → compatible?) that doesn't exist.

## 2.3 Workflow Evolution

**Then (v15-v22 era):** Solver-first. Generate metadata → fill prose templates → hope for quality. Result: metrics were good, art was bad. "Metrics eroded artistry."

**Now (v24-v34 era):** Vision-first. Choose theme → choose palettes → design 5 angles → write 21 hand-crafted scenes in PixAI block order → write 3 OC concepts → generate → validate → iterate.

**Key transitions:**
1. v24→v25: Learned that Tsubaki 2 can't render mechanisms (Poupée Mécanique failure)
2. v26→v27→v28: Learned Core OC isolation (3 iterations to get right)
3. v29→v30: Learned "camera" literalness (Tsubaki draws camera as object)
4. v31→v32: Learned cel shading self-sabotage + face geometry anchor
5. v33→v34: Learned PixAI block order (style at beginning, not trailing tag)

**What's easier now:**
- Writing prose (PixAI block order gives clear structure)
- Face consistency (face anchor + negative fixes)
- OC handling (C036 + OC_CANON.yaml + rotation rule)
- Avoiding Tsubaki 2 literalness (PH_BLACKLIST rules)
- Iterating on batches (generator scripts are recoverable artifacts)

**What's still hard:**
- Diversifying wardrobe (user noted white dresses cliché — I default to GAR01 slip dress too often)
- Camera/composition diversity (user noted lack of angles — I default to CAM01 eye-level too often)
- Making NICHE truly "superior" (atmospheric without being empty — v31 was "скучновато")
- Making VOLT truly "extremely erotic" (without being explicit — user wants "грань эротики, ебанутые и сочные")
- Balancing user's "less explicit" preference (L3=0) with C006 requirements
- Keeping 21 unique BDM when only 3 OC rotate (not an issue for main 21 since they're random)

## 2.4 Honest Self-Assessment

**What I'm good at:**
- Thematic conceptualization (5 angles, deep themes like De Profundis)
- OC concept creation (Sue's cosmos eyepatch, Sol's crystal fox ears, Nix's glass hair)
- PixAI block order prose structure
- Learning from failures (PH_BLACKLIST, constraint relaxation rationale)

**What I'm bad at:**
- Wardrobe diversity (too many slip dresses, white cotton, simple silk)
- Camera diversity (too much CAM01 eye-level, not enough Dutch tilts, from-below, from-panties-upward)
- Making VOLT prompts truly erotic without being explicit (I default to THROUGH_FABRIC which is safe but not "сочные как персики")
- Making NICHE prompts truly "superior" (I default to atmospheric emptiness, not breathtaking beauty)
- Writing diversity into pools (CAM_POOL, GAR_POOL, PL_POOL — I keep repeating the same codes)

**What surprised me:**
- How much the negative prompt mattered (cel shading self-sabotage)
- How literal Tsubaki 2 is (camera as object)
- How much architecture matters (Core OC in main 21 was a fundamental error)
- How PixAI block order fixed face drift (style at beginning, not end)
- How user feedback drives the system forward (every batch teaches something)
