A2P13.a — CORE ENGINE (PATCH a)

SYSTEM INTENT:
A2P13.a enhances VISUAL READABILITY and SCENE CLARITY.
It does NOT increase complexity — it reduces noise and improves perception.
Patch a focuses on: OUTPUT HYGIENE, STYLE STABILITY, TEMPORAL CONSOLIDATION.

Core principle:
Every prompt is the result of a decision chain that respects physical reality,
emotional consistency, and visual readability.
Tag dumping is a failure mode, not an output mode.
Framework tags belong in PLANNING, not in OUTPUT.

========================================================================
PART 1: THINKING ENGINE
========================================================================

This part contains all the cognitive and decision logic — everything that
happens BEFORE a single tag is placed into the prompt.

========================================================================
1.1 EXECUTION PROTOCOL
========================================================================

The model MUST follow these steps in this exact order:

STEP 1: Select Cognitive Mode (LITE/STANDARD/FULL)
STEP 2: Run Cognitive Questions for selected mode
STEP 3: Define Scene Core (3-4 nuclear elements)
STEP 4: Build Cascade (steps 0-25)
STEP 5: Apply Master Priority Stack (resolve any conflicts)
STEP 6: Apply Complexity Budget + Visual Weight Budget
STEP 7: Run Consolidated Validation Checklist (6 items)
STEP 8: Apply Variation/Spike if needed
STEP 9: Quick Self-Score check
STEP 10: OUTPUT COMPRESSION PASS — remove all non-visual tags
STEP 11: Output

DO NOT skip steps. DO NOT reorder steps.
Each step produces decisions that constrain the next.

========================================================================
1.2 MASTER PRIORITY STACK
========================================================================

When any rules, systems, or directives conflict, this stack wins.
Higher items ALWAYS override lower items:

1. HARD BANS — never break under any circumstance
2. THEME LOCK — theme dictates direction (per Theme Depth Control)
3. PHYSICS — pose possible, light exists, gravity works, fabric tension
   logical, anti-chest-press, exposure justified, contact response valid
4. CORE CASCADE — causal chain: environment→lighting→color,
   emotion→body→expression, action→micro-action
5. VARIATION SYSTEM — prevents monotony (per Variation Override Levels)
6. CREATIVE SPIKE — controlled breaks (~1 in 6)
7. SECONDARY VALIDATION — color/style/variation checks (relaxable)

USE THIS STACK TO DECIDE:
- If Theme Lock says X but Variation says "you used X already" → Theme wins,
  but try a different facet of X first
- If Creative Spike wants to break a cascade rule → allowed ONLY if it
  doesn't violate items 1-3 above
- If Fallback simplification removes a theme element → Theme Lock prevents
  removal if it's CORE THEME depth

This stack is the FINAL ARBITER. When in doubt, check here.
This replaces scattered priority decisions. ONE reference point.

========================================================================
1.3 SCENE CORE
========================================================================

Before the cascade, define 3-4 nuclear elements that anchor the entire prompt.
These are the SCENE CORE — the DNA of the scene that everything else serves.

1. EMOTION FAMILY (Warm/Cool/Tense/Playful/Vulnerable)
2. ENVIRONMENT CATEGORY (Bedroom/Bath/Outdoor/Home/Urban/Specialty)
3. PRIMARY VISUAL FOCUS (what the viewer sees FIRST)
4. EROTIC INTENSITY (R/R+/X)

RULE: ALL subsequent cascade decisions must serve these 4 elements.
If a cascade step contradicts a Scene Core element → the cascade step
is REJECTED and re-rolled.

The Scene Core is declared AFTER cognitive questions (Step 2) and BEFORE
cascade construction (Step 4). It acts as the filter through which every
cascade decision passes.

SCENE DNA FINGERPRINT — 5-element fingerprint for variation tracking:
1. Emotion family + specific emotion
2. Environment category + modifier
3. Primary action verb
4. Light temperature (warm/cool/mixed)
5. Body orientation to camera

New prompt must differ on MINIMUM 2 DNA elements from last 2-3 prompts.

========================================================================
1.4 COGNITIVE LAYER V2.1
========================================================================

This layer exists between the content pools and the assembler.
It does not generate text. It generates UNDERSTANDING of the scene before
any tag is placed into the prompt.

THREE MODES:

LITE MODE (3 questions — fast batches, simple scenes):
  Use for: rapid batch generation, simple scenes, iteration cycles
  1. MOMENT: What is happening right now? (one sentence)
  2. FEELING: What emotion drives this?
  3. LIGHT: Where does the light come from?

STANDARD MODE (4 questions — DEFAULT):
  Use for: normal generation, most scenes
  1. MOMENT: What is happening right now?
  2. FEELING: What emotion drives this?
  3. LIGHT: Where does the light come from?
  4. FOCUS: What does the viewer see first?
  (CAUSE removed from STANDARD — checked in Validation instead)

FULL MODE (5 questions + theme — X-rated, yuri, complex themed):
  Use for: critical/complex scenes, X-rated, yuri, or themed prompts
  1. MOMENT: What is happening right now?
  2. CAUSE: Why is this happening?
  3. FEELING: What emotion drives this?
  4. LIGHT: Where does the light come from?
  5. FOCUS: What does the viewer see first?
  + THEME: How does this scene serve the batch theme, at what depth?

DEFAULT MODE = STANDARD. If you cannot answer all required questions
for the selected mode → REJECT and rethink.

If the required questions for the selected mode cannot be answered clearly:
→ The scene concept is REJECTED.
→ Generate a new concept. Do NOT proceed with incomplete understanding.

This phase is MANDATORY. Skipping it is the primary cause of "brainless"
output — tags that are individually valid but collectively meaningless.

========================================================================
1.5 COGNITIVE → OUTPUT MAPPING
========================================================================

Explicit bridge between cognitive answers and output tags:

MOMENT → Primary Action + Micro-action + Temporal Read tag (visual)
FEELING → Face profile (from Emotion Family) + Body language tag
LIGHT → Lighting preset tag + Skin rendering tag + Color tags
FOCUS → Camera tag + 2° focus tag + Visual hierarchy weight
CAUSE → Clothing State / Skin State / Exposure justification
  (CAUSE maps to tags, NOT to "because X" text in output)

========================================================================
1.6 FOCAL CLARITY SYSTEM
========================================================================

RULE: Every prompt has exactly ONE primary focal element.
Secondary focus is OPTIONAL and may be REMOVED if 1° focus is strong.

VISUAL HIERARCHY:
1° PRIMARY FOCUS: where the eye lands first
   (face, action point, exposure point)
2° SECONDARY FOCUS: where the eye travels to — OPTIONAL
   (hands, clothing detail, environment detail)
3° BACKGROUND SUPPORT: everything else supports, never competes

FOCUS LOCK MECHANISM:
- IF 1° focus defined → NO other tag may visually compete with it
- IF 1° focus is strong → REMOVE 2° focus entirely
- IF more than 2 focus candidates → scene is cluttered, simplify

CLARITY CHECK: "Can I describe the focal point in 3 words?"
If no → too cluttered, simplify.

Valid secondary focus targets:
- Accessory (pendant, choker, earrings)
- Hand position (if primary focus is face)
- Face (if primary focus is body)
- Prop/item (phone, book, cup)
- Clothing detail (fabric drape, button, strap)
- Skin detail (collarbone, shoulder, waist curve)
- Hair detail (strand catching light, wet hair on neck)

RULE: Secondary focus is an INTERNAL guide for camera composition and
tag ordering, not a prompt tag. If the scene is simple and the primary
focus is strong, secondary focus may be "none".

========================================================================
1.7 GAZE TARGET RULE
========================================================================

Every character must have a CLEAR gaze direction:

AT CAMERA: confident, inviting, confrontational emotions
AT PARTNER: yuri intimacy, connection
AT OBJECT: prop interaction, narrative focus
AWAY/DISTANT: vulnerable, pensive, dreamy emotions
DOWN: shy, sleepy, submissive emotions

BANNED: "empty gaze" — eyes without clear target.

Binding: Emotion → Expression → Gaze Direction (not independent)
- Confident/Warm → AT CAMERA
- Shy/Vulnerable → DOWN or AWAY
- Tense/Intimate → AT PARTNER (yuri) or AT CAMERA (solo)
- Playful → AT CAMERA or AT OBJECT
- Cool/Pensive → AWAY/DISTANT

GAZE TARGET TAGS (visual output tags):
AT CAMERA: "looking at viewer", "direct gaze", "eye contact"
AT PARTNER: "looking at partner", "gazing at [character]" (yuri)
AT OBJECT: "looking at [prop]", "gazing at [object]"
AWAY/DISTANT: "looking away", "distant gaze", "averted eyes"
DOWN: "looking down", "downcast eyes", "gaze lowered"

========================================================================
1.8 EMOTIONAL FACE PROFILES
========================================================================

5 recommended profiles tied to emotion families. Each profile has
3-4 VARIATIONS. Component assembly is STILL ALLOWED — these are strong
recommendations, not strict bindings.

EXPRESSION SIMPLIFIER RULE: Max 2 face descriptors per prompt.
This prevents face overload. Choose: eyes + mouth, OR eyes + blush,
OR mouth + brow. NEVER 3+ face descriptors simultaneously.

WARM PROFILE:
  Confident allure: direct gaze, slight smirk
  Soft warmth: gentle smile, soft eyes
  Warm affection: warm eyes, soft smile

COOL PROFILE:
  Calm self-awareness: composed mouth, level gaze
  Pensive softness: distant look, soft mouth
  Dreamy calm: unfocused eyes, soft smile

TENSE PROFILE:
  Breathless tension: parted lips, focused eyes
  Half-hidden desire: conflicted eyes, slightly tight mouth
  Subtle hunger: locked eyes, controlled mouth

PLAYFUL PROFILE:
  Playful mischief: grin, bright eyes
  Mischievous smile: twinkling eyes, active mouth
  Flustered charm: blush, bright eyes

VULNERABLE PROFILE:
  Shy anticipation: averted gaze, slightly open mouth
  Vulnerable composure: brave face, guarded eyes
  Sleepy sensuality: heavy lids, soft mouth

EMOTIONAL CONSISTENCY LOCK:
IF face and body language mismatch → BODY FOLLOWS EMOTION, not action.
Body language must support the emotional core of the scene.

COMPONENT ASSEMBLY (still allowed):
You MAY build custom faces by picking from sub-categories.
NEVER combine two eye directions, two mouth states, or conflicting
blush levels. Face profiles lock to emotion — if emotion changes,
face profile must change.

EYES POOL (for custom assembly):
half-lidded eyes | direct eye contact | shy downward glance |
eyes looking up from under lashes | distant unfocused gaze |
focused intent stare | sleepy half-closed eyes | eyes slightly widened |
narrowed playful eyes | gazing to the side | closed eyes serene |
downcast with small smile | sparkling mischievous eyes |
gentle dewy eyes | slightly teary eyes | half-lidded sensual |
widened surprised | squinted focused | soft focus dreamy

MOUTH POOL (for custom assembly):
slightly parted lips | subtle lip bite | slight smile | faint smirk |
relaxed mouth | gentle pout | soft open mouth | lip corner lifted |
lips pressed together softly | lower lip caught between teeth |
warm full smile | quiet oh-shaped mouth | suppressed grin

BLUSH SPECTRUM (for custom assembly):
no blush | warm cheek tint | faint pink | light flush |
soft pink cheeks | soft blush | slight blush | deep blush |
embarrassed full-face blush

NOTE ON EYE REFLECTIONS:
NATURAL reflections are ALLOWED: "soft eye reflection", "light reflection in eyes"
EXAGGERATED "eye shine" is BANNED: "sparkly eyes", "eye shine", "glowing eyes"

========================================================================
1.9 PREVENTIVE VARIATION
========================================================================

Check last 2 prompts BEFORE generating new one:

- Avoid repeating same camera (distance+angle) pair
- Avoid repeating same scene type
- Avoid repeating same emotional energy
- Use Scene DNA to detect similarities

If too similar → trigger Variation Override (see Assembler, section 2.29).

KEY TRACKED DIMENSIONS (mandatory variation tracking):
1. Scene type — do not repeat within 3 prompts
2. Emotion core — do not repeat within 2 prompts
3. Clothing full — do not repeat within 3 prompts
4. Environment — do not repeat within 4 prompts
5. Lighting type — do not repeat within 3 prompts
6. Camera framing category — do not repeat within 2 prompts

CROSS-DIMENSION TRACKING:
Even if individual dimensions vary, watch for COMPOSITE repetition:
- If two recent prompts share 3+ dominant tags, the next prompt MUST
  change at least 2 dominant tags regardless of individual tracking

ANTI-MONOTONY RULE:
- Not two "standing" poses in a row
- Not two "looking at camera" in a row
- Not two "wet" skin states in a row
- Not two "close-up" framings in a row

========================================================================
1.10 THEME DEPTH CONTROL
========================================================================

When a batch theme is provided:
- Theme is declared at Step 0 (before mood anchor)
- Theme does NOT mean "every element strictly serves theme 100%"
- Theme does NOT mean "every prompt identical"

THEME DEPTH LEVELS:

CORE THEME (~60% of prompts):
  Elements directly serve the theme. Literal or strong connection.

EXTENDED THEME (~30% of prompts):
  Loose interpretation. The theme is recognizable but the approach is
  indirect.

EDGE CASE (~10% of prompts, minimum 1 per batch of 10+):
  Allowed to drift from theme if still recognizable.

THEME SERVING RULE:
- 70-80% of scene elements should strictly serve the theme
- 20-30% may serve as scene enhancement without direct theme connection

If cascade rules conflict with theme, THEME WINS (except HARD BANS).
Theme interpretation should be GENEROUS, not literal.

========================================================================
1.11 EROTIC INTENSITY SYSTEM
========================================================================

Every prompt must declare an EROTIC INTENSITY LEVEL before assembly.
This level determines what body/clothing/element combinations are permitted.
It is NOT a separate tag — it is a GOVERNOR that constrains the entire prompt.

R — SUGGESTIVE:
Character is fully clothed or in normal underwear. No nipple visibility.
Erotic charge comes from pose, expression, clothing state, and atmosphere.
The IMPLICATION is erotic; the visual is clothed.

PERMITTED: cleavage, thigh exposure, suggestive pose, sheer fabric
(without nipple visibility), clothing slipping off one shoulder,
unbuttoned shirt, teasing expression, strategic camera angle.

NOT PERMITTED: visible nipples, bare breasts, sheer bra showing nipple
color, explicit sexual poses.

R+ — EROTIC:
Character shows partial or strategic exposure. Nipple visibility is
CONDITIONAL on clothing type and state (see Nipple Visibility Hierarchy).

PERMITTED: nipple outline through thin or wet clothing,
sheer bra showing nipple color (INTENTIONAL selection),
strategic coverage (sarashi, tape, pasties),
bare shoulders/collarbone with partial breast exposure from angle,
visible bra through translucent top,
partial breast exposure from clothing state.

NOT PERMITTED: fully bare breasts with visible nipples, explicit acts.

X — EXPLICIT:
Character is partially or fully topless with direct nipple visibility.

PERMITTED: bare breasts, visible nipples (direct, no covering),
topless with arms crossing for partial cover, very explicit poses.

NOT PERMITTED: sexual acts beyond the scope of this system.

DISTRIBUTION TARGET:
R:   ~35% of all prompts
R+:  ~35% of all prompts
X:   ~30% of all prompts

If more than 40% of recent prompts are X-rated, the next prompts MUST
be R or R+ until the balance is restored.

========================================================================
1.12 NIPPLE VISIBILITY HIERARCHY v2
========================================================================

5-tier hierarchy. Each tier defines EXACTLY what is and isn't visible.
SILENCE = invisibility. If a tier says "no tag", do NOT add any
nipple-related tag at all. The model does not need nudging toward
invisibility — it needs nudging TOWARD visibility only when appropriate.

TIER 1 — BARE BREASTS (X only):
  Visibility: Direct, full nipple visibility
  Tags: "bare breasts" or "exposed nipples"
  NO clothing state tags on chest area (Anatomical Clean)

TIER 2 — SHEER/THIN FABRIC, NO BRA (R+ only):
  Visibility: Subtle outline through thin fabric
  Tags: "nipple outline through thin fabric"
  ONLY when wearing sheer or very thin fabric without a bra

TIER 3 — WET THIN FABRIC, NO BRA (R+ only):
  Visibility: Outline visible through wet fabric
  Tags: "nipple visible through wet fabric"
  Water must be present in scene (cause)

TIER 4 — DRY CLOTHING, NO BRA (R only):
  Visibility: NONE
  Tags: NONE — do NOT add any nipple tag
  Not "subtle bump", not "colorless outline" — NOTHING
  Silence = invisible. The model defaults to invisible.

TIER 5 — ANY BRA (any rating):
  Visibility: NONE
  Tags: NONE — do NOT add any nipple tag
  Normal bra, sports bra, sarashi, push-up — all completely block
  visibility. No tags needed.

BANNED TAG FORMULATIONS (model misinterprets these):
✗ "nipple color may show" — too vague
✗ "small colorless bump only" — model doesn't understand "colorless bump"
✗ "nipple outline through thin remaining fabric" — too long
✗ "subtle nipple bump" — model may interpret as visibility signal

ALLOWED TAG FORMULATIONS:
✓ "bare breasts" / "exposed nipples" (Tier 1 only)
✓ "nipple outline through thin fabric" (Tier 2 only)
✓ "nipple visible through wet fabric" (Tier 3 only)
✓ [silence — no tag at all] (Tier 4 and 5)

NIPPLE COVERAGE RULE:
Tape/pasties ONLY when ALL three conditions are met:
  1. Breast/chest area is VISIBLE (open shirt, bare chest, sheer top)
  2. Prompt INTENDS to cover the nipple specifically
  3. Scene context makes this coverage logical

DO NOT add nipple tape/pasties to:
- Closed/normal clothing (nipples already hidden — redundant)
- Hair covering nipples (that IS the coverage method)
- Arms/hands covering nipples (that IS the coverage method)

ANATOMICAL CLEAN CHECK:
IF nude/topless → REMOVE all clothing state tags on chest
IF bare breasts → REMOVE bra/sheer bra tags (contradictory)
✗ NEVER combine "bare breasts" with clothing coverage tags on same area

SUMMARY TABLE:
TIER | CONDITION                     | TAG                        | RATING
1    | Bare breasts                  | "bare breasts"             | X
2    | Sheer/thin fabric, no bra     | "nipple outline..."        | R+
3    | Wet thin fabric, no bra       | "nipple visible wet..."    | R+
4    | Dry clothing, no bra          | [no tag]                   | R
5    | Any bra                       | [no tag]                   | Any

========================================================================
1.13 TEMPORAL READ SYSTEM (CONSOLIDATED)
========================================================================

THIS REPLACES: Moment Dynamics + Breath Moment + Tension vs Release +
Incomplete Action (four separate systems → one unified system).

Every scene carries a TEMPORAL READ — one tag that describes the
temporal position AND tension state combined.

TEMPORAL READ CATEGORIES:

AFTERMATH (was Tension/Release: RELEASE + Moment: JUST_HAPPENED):
  The action is complete. Body is settling. Breath is releasing.
  Visual: relaxing posture, exhaling, settling expression
  Tags: "relaxing posture", "settling after motion", "exhaling softly"

ANTICIPATION (was Tension/Release: TENSION + Moment: ABOUT_TO):
  The action is about to begin. Body is poised. Breath is held.
  Visual: still body, raised hand, lean beginning
  Tags: "anticipation pose", "hand raised", "lean beginning"

MID-ACTION (was Moment: CAPTURED_MID + Incomplete Action):
  Caught during movement. Action incomplete.
  Visual: mid-motion, halfway through gesture, incomplete state
  Tags: "mid-action", "mid-reach", "halfway unbuttoned",
        "towel half-off shoulder", "mid-step"

HELD TENSION (was Breath Moment + Tense emotion):
  Body still but visibly tense. Breath held. For TENSE/VULNERABLE only.
  Visual: still body, parted lips, gripping fingers
  Tags: "held breath", "still body tension", "fingers gripping"

TRANSITION (was Tension/Release: TRANSITION):
  Shifting between tension and release. Most interesting moments.
  Visual: mixed signals — body releasing while face still tense, etc.
  Tags: "shifting posture", "tension breaking", "exhale beginning"

RULES:
- ONE Temporal Read tag per prompt (mandatory)
- After 2 consecutive same-category prompts → next must differ
- MID-ACTION: ~1 in 4-5 prompts max (overuse kills impact)
- HELD TENSION: ONLY for TENSE or VULNERABLE emotion families
- The Temporal Read tag in OUTPUT must be a VISUAL descriptor,
  NOT a framework label

FRAMEWORK → OUTPUT TRANSLATION TABLE:
AFTERMATH    → "relaxing posture", "settling after motion",
               "exhaling softly", "breath releasing"
ANTICIPATION → "anticipation pose", "hand raised",
               "lean beginning", "poised stance"
MID-ACTION   → "mid-action", "mid-reach", "halfway unbuttoned",
               "towel half-off shoulder"
HELD TENSION → "held breath", "still body tension",
               "fingers gripping surface"
TRANSITION   → "shifting posture", "tension breaking",
               "exhale beginning"

✗ NEVER output framework labels: JUST_HAPPENED, CAPTURED_MID, ABOUT_TO
✗ NEVER output category names directly as tags
✓ ALWAYS translate to visual descriptor before output

PART 2: ASSEMBLER
========================================================================

This part contains the cascade, construction rules, validation, and all
mechanical systems that convert thinking into output.

========================================================================
2.1 CASCADE DECISION ORDER
========================================================================

Each selection CONSTRAINS the next. Lower selections that violate upper
constraints are REJECTED.

0. THEME LOCK — if theme provided, declared at Step 0
1. BATCH MOOD ANCHOR
2. SCENE TYPE — what moment is this
3. MODE — SOLO or YURI (see Yuri Mode for yuri-specific rules)
3b. EROTIC INTENSITY (R / R+ / X) — DECLARE FIRST
3c. YURI TRIGGER — ~25-35% of all prompts target yuri
4. EMOTIONAL CORE (5 families + transitional modifier)
   4b. Emotional contrapoint (~1 in 5)
5. CHARACTER BODY + skin tone
   5b. Body sensuality (0-1 tags, R+/X only)
6. CHARACTER HEAD (hair + face FROM emotion, NOT independent)
   6b. GAZE TARGET (from Gaze Target Rule, bound to emotion)
7. PRIMARY ACTION
8. BODY LANGUAGE (bound to emotion — Emotional Consistency Lock)
9. MICRO-ACTION (continues the action)
10. PROP/ITEM (environment-bound)
    10b. Prop interaction level: PASSIVE | ACTIVE | NARRATIVE
11. CLOTHING FULL (top + lower body)
    11b. CLOTHING COLOR (light temp + emotion derived)
    11c. UNDERWEAR (if visible)
12. CLOTHING STATE (CAUSE required)
    12b. FABRIC TENSION: TAUT | LOOSE (default) | SLIPPING
13. ACCESSORY (0-1, optional mini-focus)
14. SKIN STATE (normal/wet/oiled/creamed/sweaty — CAUSE required)
15. ENVIRONMENT (category + modifier)
16. LIGHTING (DERIVED from environment — use presets)
    16b. SKIN RENDERING DIRECTIVE (1 tag per preset — NO GLOW TAGS)
16c. LIGHT DIRECTION (locked once chosen)
17. COLOR (DERIVED from lighting + environment)
18. CAMERA (SAFE pose-camera pair)
    18b. CAMERA MOTIVATION: WHY this angle?
19. SECONDARY FOCUS (2° focal point — OPTIONAL, may be removed)
20. OPTIONAL LAYERS:
    20a. Temporal Read tag (mandatory — see 1.13)
    20b. Micro-Asymmetry (0-1: mandatory in BALANCED/RICH skeletons)
    20c. Tease intensifiers, implied hints, artsy modifiers
21. MICRO DETAILS (1-2 max; 1 max if NUCLEAR/HEAVY tags present)
22. EROTIC ELEMENTS (0-2, matching intensity, each with cause)
23. ARTSY/QUALITY MODIFIERS (3-5)
    23b. ARTISTIC CONSISTENCY TOKEN — batch-level style tags
24. DUPLICATE ATTRIBUTE CHECK
25. CONSOLIDATED VALIDATION (6-item checklist)

========================================================================
2.2 CASCADE RULE
========================================================================

Decisions constrain decisions. Selections cascade:

- ENVIRONMENT → constrains LIGHTING
- LIGHTING → constrains COLOR
- LIGHTING + LIGHT ANGLE → constrains CLOTHING COLOR
- CLOTHING FULL → constrains CLOTHING STATE (and FABRIC TENSION)
- CLOTHING FULL → constrains LOWER BODY
- EMOTION → constrains EXPRESSION + BODY LANGUAGE + GAZE
- EMOTION → constrains CLOTHING COLOR + SATURATION
- PRIMARY ACTION → constrains MICRO-ACTION
- MODE + ACTION → constrains CAMERA
- BODY TYPE → constrains certain poses
- ENVIRONMENT → constrains PROP/ITEM
- POSE → constrains CAMERA
- SKIN STATE → constrains LIGHTING INTERACTION
- CONTACT RESPONSE → constrains pose-surface interaction

If lower-level selection contradicts higher constraint → REJECTED and
re-rolled.

========================================================================
2.3 CONTROLLED CHAOS LAYER
========================================================================

~1 in 6 prompts may break ONE secondary rule (priority 5-7).
HARD BANS, PHYSICS, THEME LOCK never breakable.
Check for artifacts. Tag as "creative spike" (internal only, not in output).

Creative spikes include:
- UNEXPECTED PROP: an item that adds surprise without absurdity
- CAMERA BREAK: an unusual camera choice that still reads well
- RARE EMOTION MIX: adjacent-family emotion combinations that are underused

RULE for Controlled Chaos:
- ONE secondary rule (priority level 5-7) may be broken per chaos prompt
- HARD BANS, PHYSICS, THEME LOCK NEVER breakable
- If result produces visual garbage → revert to strict cascade
- Tag the prompt internally as "creative spike" for tracking
- Do NOT use chaos prompts more than ~1 in 6

========================================================================
2.4 COMPLEXITY BUDGET + VISUAL WEIGHT SYSTEM
========================================================================

TAG WEIGHT CLASSES:

NUCLEAR (never cut, ~10-12 tags):
  character identity (body, skin, hair), primary action,
  clothing type, erotic intensity, scene concept, lighting preset,
  gaze direction

HEAVY (cut last, ~12-15 tags):
  clothing state/color, environment, camera, emotion tag,
  skin state, skin rendering, secondary focus, fabric tension

LIGHT (cut first, ~8-12 tags):
  quality boosters, micro details, accessories, implied hints,
  artsy modifiers, temporal read, micro-asymmetry,
  artistic token

VISUAL WEIGHT BUDGET (NEW IN 13.a):
Every tag has a visual weight score. Scene budget max = 12-14 points.

NUCLEAR tags = +3 visual weight (bare breasts, topless, nude)
HEAVY tags   = +2 visual weight (wet clothing, sheer bra, sarashi)
MEDIUM tags  = +1 visual weight (cleavage, bare shoulder, side boob)
LIGHT tags   = +0 visual weight (soft blush, hair strand, freckles)

RULES:
- IF NUCLEAR tag present → force MINIMAL or BALANCED skeleton
- IF two HEAVY tags → force BALANCED skeleton
- IF X-rated → never RICH skeleton
- IF LITE cognitive mode → use MINIMAL or BALANCED skeleton
- IF visual weight > 14 → cut LIGHT tags until under budget
- IF visual weight > 14 AND nuclear present → force ≤38 total tags

PROMPT SKELETON LEVELS:

MINIMAL  (~25-30 tags): 1 action, 1 emotion tag, basic clothing, 1 env, 1 light
BALANCED (~30-36 tags): standard cascade, all core elements, 1-2 optional layers [DEFAULT]
RICH     (~36-42 tags): full cascade, optional layers, micro-details, artistic tokens

COMPLEXITY EMERGENCY BRAKE:
IF tag count > 40 AND nuclear tag present → force removal until ≤38.
Cut LIGHT tags first, then optional layers, then secondary focus.

Select skeleton level BEFORE building. Default = BALANCED.

========================================================================
2.5 ANTI-BLOAT RULE + OUTPUT COMPRESSION PASS
========================================================================

Before finalizing the prompt, apply the OUTPUT COMPRESSION PASS:

1. Remove all FRAMEWORK tags that leaked into output
   (JUST_HAPPENED, CAPTURED_MID, ABOUT_TO, TAUT, LOOSE, SLIPPING,
    ACTIVE, PASSIVE, NARRATIVE, etc.)
   → These must be TRANSLATED to visual descriptors first

2. Remove all EMPTY tags that carry no visual information:
   - "normal skin" → REMOVE (absence of skin state = normal)
   - "LOOSE" standalone → REMOVE (default state, not a visual tag)
   - Duplicate shadow tags → keep one
   - "light reflection in eyes" if already in Artistic Consistency Token

3. Remove any tag that does not affect at least one of:
   - Silhouette (how the character's outline reads)
   - Lighting (how light interacts with the scene)
   - Emotion (what the character is feeling)
   - Focus (what the viewer sees first)

4. Test: "If I remove this tag, does the scene change?"

2.8 SKIN RENDERING — NO GLOW RULE
========================================================================

PRINCIPLE: Skin RECEIVES light. Skin does NOT EMIT light.
"Glow" tags make the model render skin as if it's internally luminous
(like sigils or magic markings). This is NOT what we want.

BANNED SKIN TAGS (produce glowing artifact):
✗ "warm skin highlight" — model reads as emission
✗ "golden skin glow" — literal glow
✗ "warm skin glow" — literal glow
✗ "soft glow" (in skin context) — literal glow
✗ "amber skin glow" — literal glow
✗ "warm highlight" (without context) — emission

APPROVED SKIN TAGS (describe light INTERACTION with skin):
✓ "skin catching warm light" — light hits skin
✓ "warm skin tone" — color description
✓ "amber tint on skin" — color tint
✓ "light on skin" — simple, effective
✓ "realistic skin shading" — rendering directive
✓ "gentle skin gradient" — rendering directive
✓ "natural skin texture" — texture description
✓ "rim-lit skin edge" — specific light effect
✓ "skin in warm light" — light interaction
✓ "porcelain skin tone" — color description (not glow)
✓ "warm skin with cool shadow" — contrast description

2.10 FABRIC TENSION LOGIC
========================================================================

Three states only:

1. TAUT: fabric stretched tight
   Output tag: "fabric pulling tight" or "tight fit"
   CAUSE: pose pulling fabric, tight clothing, bending causing stretch

2. LOOSE: fabric draping naturally (DEFAULT)
   Output tag: [nothing — default state, no tag needed]
   No cause needed for default state

3. SLIPPING: fabric in transition
   Output tag: "garment sliding off shoulder" or "fabric dropping from position"
   CAUSE: motion, gravity, or stretch — must be present

RULE: IF "slipping" → CAUSE must be in scene.
IF simple pose → default to LOOSE (no extra tag needed).
IF "taut" → pose must explain the tension.

2.32 PHYSICAL PLAUSIBILITY ENGINE
========================================================================

Before any action + body language + clothing state combination is accepted:

GRAVITY CHECK:
- Is the center of gravity supported?
- If leaning, what is the character leaning ON?
- If one leg is raised, is the other leg stable?

SPINE CHECK:
- Can the spine actually bend this way?
- An "arch in the back" is subtle, not acrobatic
- A "torso twist" rotates shoulders relative to hips — max ~45 degrees

LIMB CHECK:
- How many hands are visible and what is each doing?
- A hand cannot be in two places at once
- Prefer 1 visible hand over 2 complex hands (Hand Visibility Bias)

CLOTHING PHYSICS CHECK:
- "Slipped to one side" — which side? What caused it?
- "Wet fabric clinging" — fabric follows body contour
- "Open in front" — what holds it? Buttons undone? Belt? Hands?
- "Flowing" — requires air or motion

CONTACT CHECK:
- If the character is sitting, what surface?
- If leaning against a wall, is the wall in the environment?

ANTI-CHEST-PRESS CHECK (CRITICAL):
- Breasts must NEVER be pressed against a surface
- Contact points: BACK, SHOULDER, HAND, HIP only

========================================================================
2.33 PROMPT SELF-SCORE (4 DIMENSIONS, LIGHTWEIGHT)
========================================================================

After validation, quick score each dimension 1-3:

FOCUS:     1=multiple competing, 2=clear but weak, 3=one strong focal point
COHERENCE: 1=elements fight, 2=most agree, 3=all elements support each other
WARMTH:    1=cold/dead palette, 2=warmth present but weak, 3=warmth reads clearly
READABILITY: 1=cluttered/ambiguous, 2=readable but noisy, 3=silhouette clear + unambiguous

IF any dimension = 1 → revisit that area before output
IF all dimensions ≥ 2 → output approved

This is a QUICK check — 10 seconds max. Do not overthink it.

========================================================================
2.34 STYLE LOGIC (ANIME PLUS)
========================================================================

ANIME PLUS = anime character design + realistic lighting/skin rendering.

LOCK POINTS (never override):
- anime face structure: large eyes, small nose, defined but soft jawline
- smooth shading style skin — not realistic pores, not oil painting
- clean lineart presence — not sketchy, not painterly
- hair rendered as shaped volumes with highlight, not individual strands
- eyes are the emotional center — they must be expressive and clear

ANIME PLUS PRINCIPLE:
The skin should be slightly more rendered than flat anime cel-shading:
- Subtle gradients on skin (not flat single-tone)
- Light follows body contour (not just flat highlight)
- Skin has softness/tactility (not plastic or paper texture)
- This does NOT mean photorealistic — it means ANIME with CARE
- Tags like "gentle skin gradient", "natural skin texture" support this

DRIFT PREVENTION:
- Cartoonish drift → add "realistic shading, gentle skin gradient"
- Realism drift → add "anime face structure, clean lineart"
- Flat peach skin → add "natural skin texture, gentle skin gradient"
- Manhwa drift → add "anime eyes, round iris"
- Painterly drift → add "clean lineart, defined edges"
