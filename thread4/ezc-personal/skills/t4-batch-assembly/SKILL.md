# T4 Batch Assembly (конвейер и бюджетная математика)

## Конвейер

```
draft (автор через UI / CLI)
  → gen-rawplus --from-draft T4-NN [--exp N] [--weights]
  → писец (scribe): черновик слотов, круги ремонта
  → гейты (dry): hard должны стать PASS
  → сдача (deliver) → летопись: batch.delivered
  → вердикт автора (глаз) → TASTE.md / RENDERER_FACTS.md / законы
```

- Писец пишет слоты пачками; круг ремонта поднимает только упавшие блоки.
  Заголовок слота модель пишет с хвостом («### P01 — anchor») — парсер
  толерантен (фикс ce4a1f6), но не полагайся: 4 круга = потолок, дальше
  честный FAIL и квитанция в летопись.
- Сдача с проваленным hard-гейтом закрыта честно: scribe.drafted с
  hardPass:false + долг в ворклог. НЕ молчи о провале.

## Бюджетная математика окна палитр

- Фонд палитр: **105** (palettes.json).
- Окно = 105 − потреблённое прошлыми батчами. Пример из T4-32:
  T4-29+30+31 съели 79 → окно 26.
- Каждый слот берёт палитру; **EXP-слоты берут палитры ВНЕ окна**
  (уже занятые окном не подходят).
- Правило физики: слотов с палитрами ≤ окно + EXP.
  EXP=8 при 24 основных → 28 палитр > 26 окна — **невозможно**.
  Легальный максимум в том раскладе был EXP=4.
- Дефицит палитр НЕ решается молча: доложи автору варианты
  (расширить фонд — вкусовое решение автора; сузить окно — закон).

## weights_raw (легализация, рецепт v1.9.0)

- Диапазон **0.8–1.2**, максимум **3 слота** на батч с весами.
- Вес усиливает существующий сигнал — **канал весом не обходится**
  (нет P30-коктейля → 1.2 не нарисует бугорки).
- A/B-пары — живой тест легализации: половина A с весом, половина B без;
  вердикт автора покажет, работает ли рычаг.

## A/B-пары и REHAB

- Пары κ/λ/μ: одинаковый lead, разные половины; в вердикт автора —
  атрибуция по половинам (позиция, мой тир, заявка, дельта).
- REHAB-слоты: канал доставки, провалившийся в прошлом вердикте,
  становится главным сигналом кадра (добор по вердикту автора).
