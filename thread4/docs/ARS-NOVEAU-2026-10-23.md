# ARS NOVEAU — концепт новой эры раскрытия темы

**Принято приказом автора 2026-10-23. Кодовое имя исполнителя — Доу.**
Ветка: `thread4.1` (перезалит от `main` @ 8a07b17; прежний кончик ветки —
9357a29, фазы 4–6 до cutover, функционально поглощены эрой «МОЩНОСТЬ»).

## 1. Что умерло и почему

Старый раскры́ватель (гейт №25, theme.rs v1.0.0) раскладывал ТЕМУ в один
набор якорей на весь батч (~10 измерений: локейшн/время/свет/мотивы/…) и
мерил adherence всего текста к этому набору. Против него три факта:

1. **Одна вселенная на 24 кадра** — тема раскрыта ОДНИМ способом, слоты
   читаются как вариации одного кадра (T4-32: «стерильно» ×14).
2. **Кубик вместо мысли** — якоря выбирались сидом; лексикон перехватывал
   3 измерения из 10. Тема не ДУМАЛАСЬ.
3. **Сюжет слота не существовал** — писец получал механику (поза/палитра/
   стек/дресс) и обязан был САМ изобрести сцену на лету. T4-45 это поймало
   честно: «темы ОС вплетены в THESIS/Spine, но ПОТЕРЯНЫ в POS», «P03 нёс
   генерический тезис батча вместо сюжета слота», «EXP понят как пустой
   стек». Сюжет надо изобретать ДО писца — отдельной инстанцией.

## 2. Доктрина ARS NOVEAU

**ARS NOVEAU** — раскры́ватель темы нового поколения. Действует через мост
с доступом к LLM (единый провайдер писца, `T4_SCRIBE_PROVIDER`): ему
отправляется тема — он думает и строит **21 отдельную историю мейн-пула**
(одна история = один слот = один способ, которым тема раскрывается в ЭТОМ
кадре) + **3 истории ОС** (своя история на каждую ОС-тему автора) +
**EXP-идеи** (вне темы, см. §5). Одним актом он же изобретает спайн батча
(движок/закон/теза/акты/тема-слова) — отдельный этап «Сборка» (спайн)
упразднён, его работа поглощена.

Жанровый микс 21 истории назначается по политике (`policy.law`): сколько-то
ниш, пара экскуизитов, остальное — волт. Точная пропорция — в
`policy.ars.mix`.

### 2.1 Поля истории слота

Каждая история несёт ВСЁ, что должно быть в итоговом рендере:

| Поле | Смысл |
|---|---|
| `genre` | NICHE / VOLT / EXQUISITE (мейн) или OC (ос-истории) |
| `title` | имя истории (2–4 слова, для автора) |
| `reveal` | ЧТО тема раскрывает именно в этом слоте (одним предложением) |
| `scene` | сцена: что происходит в кадре |
| `environment` | окружение: место, предметы, физика мира |
| `vibe` | вайб: настроение кадра (drawable-подача, не абстракция) |
| `lighting` | освещение: источник, направление, характер |
| `poseIdea` | идея позы (словами; финальную позу назначит компилятор из библиотеки — идея задаёт НАПРАВЛЕНИЕ) |
| `outfit` | одежда: концепт аутфита (МЕРДЖ с Дрессером: канал/тон/состояние назначает машина — конфликт решает Дрессер, №28/№29) |
| `character` | персонаж: волосы/цвет, строение тела, кожа, раса-механика (для ОС — что канон НЕ закрывает: подача канона в этой истории) |
| `witness` | (опц.) объект-свидетель — третий глаз кадра |
| `dice` | (опц.) требование ULTIMATE DICE: ритм/структура тег-рана, которые история диктует |
| `thesis` | закон кадра одной строкой (идёт писцу как THESIS-зерно) |

### 2.2 Законы историй

- Истории пишутся **англ. drawable-словами**: каждое существительное — то,
  что рендерер нарисует. Абстракции («dreamlike», «mysterious») запрещены
  (§ NICHE LAW, квитанция T4-11).
- Заголовок темы НЕ вплетается в историю дословно (закон №26).
- Вечные флоры (anti-loli, leak, candle) в истории не заходят — гейт
  плана ловит.
- Истории 21 мейна различаются СЦЕНОЙ и ЗАКОНОМ кадра, не только словами:
  гейт плана мерит уникальность thesis.

## 3. Сборщик

Сборщик — упаковщик для писца (детерминированный, БЕЗ LLM, Rust): берёт
механический контракт (канон-реестр + бриф: позы/палитры/стеки/лиды/дресс/
дайсы/варьety) и истории ARS NOVEAU, и складывает **брикеты** — по одному
на слот, «чтобы писцу было максимально понятно, что ему писать». В брикет
вшиты долги T4-45 как константы:

- **OC-закон**: тема/история ОС обязана дойти до POS-ТЕГОВ (не только
  THESIS/Spine) — квитанция T4-45 (а).
- **EXP-закон**: EXP = без темы, НО core-4 стек + отличный кадр — квитанция
  T4-45 (в). Гипотеза EXP приходит из ARS-идеи.
- **on_skin-контр-NEG**: канал on_skin несёт `nipples exposed, areola` в
  NEG — квитанция T4-45 (д).
- **Полные ID палитр** для EXP — квитанция T4-45 (г).

Гейт сборщика: брикет на каждый слот контракта; в каждом брикете история;
жанр истории не спорит с kind слота (спор — механика побеждает, история
адаптируется писцом); EXP-брикет несёт идею+стек; OC-брикет несёт историю.

Артефакты: `data/rehearsals/briquettes/<slug>.json` (+ `.md` для автора).

## 4. Писец

Без изменений в механике (чанки ≤6 → батарея → ремонт ≤3 → полировка), но
slotFrame теперь открывается STORY-блоком из брикета: писцу больше не нужно
изобретать сцену — он «просто добавь воды»: переводит историю+механику в
POS/NEG по регламенту (POS = тег-ран RAW+, NEG-флоры + counter-NEG канала).

## 5. EXP-слоты — вне темы

EXP больше не связан с темой ВООБЩЕ (развитие вердикта T4-34): EXP-идеи
живут в ARS NOVEAU отдельным списком и нужны ТОЛЬКО чтобы что-то проверить
на успех: концепт ниши, новую позу для волт, часть одежды, новый кин,
нового ОС (подтверждение канона). Гейт чистоты: тема-слова не заходят в
EXP-идеи; брикеты EXP несут гипотезу + A/B-дисциплину одной переменной.

## 6. FURNACE (Печь)

Последняя инстанция перед сдачей — агент-оценщик на LLM (через мост, тот
же провайдер). Ему дают: черновик батча, брикеты, квитанции гейтов. Он
смотрит, ЧТО налепили предыдущие инстанции:

1. **Гейты** — что поймали, что ПРОПУСТИЛИ (сверка находок с текстом);
2. **Тема** — раскрыты ли 21 история в кадрах (адресно, по слотам);
3. **Писец** — сделал ли работу: фейс-лок, канон-вербатим, форма тег-рана,
   NEG-флоры, бюджет тира, контр-NEG каналов;
4. **Итог** — что получилось, что нет, и почему.

Репорт — обширный и без пиздежа: `data/rehearsals/reports/<slug>-furnace.md`
+ событие `furnace.reported`. Вердикт PASS/WARN/FAIL:
- PASS/WARN — конвейер идёт дальше;
- FAIL — автосдача стопится; ручная сдача требует ЯВНОГО решения автора
  (`furnaceOverride` в брифе, событие фиксирует) — §1: автор владеет
  вкусом, машина владеет консистентностью.

## 7. Конвейер (новая operational order)

```
1. ARS NOVEAU   «Раскрытие»   — тема → спайн + 21 история + 3 ОС + EXP-идеи (LLM-мост)
2. КОМПИЛЯЦИЯ   «Канон»       — реестр канона (ротации, окно) + бриф писца
3. СБОРЩИК      «Брикеты»     — истории × механика → брикеты для писца
4. ПИСЕЦ        «Промпты»     — чанки по брикетам → POS/NEG + батарея + ремонт
5. ПЕЧЬ         «FURNACE»     — LLM-оценщик → честный репорт
6. СДАЧА        «DELIVER»     — полная батарея + фиксация в хеш-цепи
```

Тайминги моста: ARS — до 4 LLM-вызовов (спайн+ОС+EXP, потом 21 история
тремя актами по 7); Печь — 1 вызов. Всё compute-only на стороне Node,
единственный писатель летописи — Rust-движок.

## 8. Регресс и совместимость

- `theme.rs` остаётся в дереве (RPC `/theme/expand`, selftest, откат),
  но из конвейера выключен: его роль играет `ars.rs`.
- Старые прогоны (5 этапов) восстанавливаются с маппингом:
  theme→ars, build→collector, furnace вставляется pending перед deliver.
- Byte-parity канона (sha10) не тронут: ARS-артефакты живут ВНЕ
  канонического плана (доктрина theme-эры сохранена).
- Гейт adherence №25 теперь мерит текст против ТОКЕНОВ ИСТОРИЙ слотов
  (per-slot), а не против одного набора якорей батча.

## 9. DoD эры

1. Батч = 3 ОС + 21 мейн (закон 24) + EXP-оверлей (до 9, policy).
2. Каждый мейн-слот рождается из СВОЕЙ истории (гейт: thesis уникальны).
3. Писец не изобретает сцену — только переводит брикет в теги.
4. Ни один батч не сдаётся без репорта Печи.
5. Ручная доводка остаётся законным путём (T4-45 доктрина) — Печь
   обязана ВИДЕТЬ разрыв «брикет ↔ черновик», а не красить его.
