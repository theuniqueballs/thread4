# ARS NOVEAU — хартия Раскрывателя темы (v1.0.0)

Рождено приказом автора (смена 2026-10-24, кодовое имя исполнителя — Доу).
Статус: действующий конвейер на ветке `thread4.1`, ядро — Rust (`t4-engine-rs`), LLM — через мост.

## 1. Суть

Старый раскрыватель («фраза → три микро-темы») устарел. **ARS NOVEAU** действует через мост с
доступом к LLM: ему отправляется тема — он думает и строит **21 слот по теме** (мейн-пул) +
истории **3 ОС** по своим темам + **EXP-программу**. Распределение мейнов по архетипам:
часть — **НИША** (NICHE), пара слотов — **ЭКСКУИЗИТ** (EXQUISITE), остальное — **ВОЛЬТ** (VOLT).

**EXP-слоты — вне темы.** Они не считаются связанными с темой вообще. Они существуют ТОЛЬКО
чтобы проверить что-то на успех: концепт ниши, новую позу для вольта, часть одежды, новое кино,
или кандидата в новые ОС. Канон T4-34 сохраняется: EXP — машинные болванки, ноль свободы писца.

## 2. Пайплайн

```
ТЕМА (+1..3 ОС-темы)
   ↓  ARS EXPAND (LLM через мост :3202)
33 слот-карточки: 3 OC + 21 main + 9 EXP-программа
   ↓  СБОРЩИК / ASSEMBLE (Rust, детерминирован)
БРИКЕТЫ — по одному на слот + скелет батча (движок-машинное всё)
   ↓  ПИСЕЦ / SCRIBE (LLM через мост, чанки по 6)
POS-тег-раны (RAW+) + NEG-EXTRA; NEG-флооры строит машина
   ↓  ГЕЙТЫ (textgates.rs, 30+ квитанций, in-process)
hard PASS / честный список FAIL
   ↓  FURNACE (LLM-оценщик через мост)
обширный честный репорт: что получилось — а что нет
   ↓  ПЕЧЬ (сдача — существующий deliver-контур прод-движка)
```

Каждая стадия — асинхронная задача twin'а (`:3201`): POST запускает поток-работник и отвечает
мгновенно; прогресс читается GET-ом сессии. Двойной замок командира сохранён (Next-прокси + twin).

## 3. Слот-карточка ARS (что входит)

| Поле | Кто решает | Куда попадает |
|---|---|---|
| `reveal` — что раскрывает тема в этом слоте | LLM | THESIS + брикет (THEME REVEAL LAW: акт-грань DISCOVERY/ESCALATION/CONSEQUENCE + drawable presence) |
| `scene` — сцена кадра | LLM | брикет → POS |
| `environment` — ENV01-12 | LLM (валидация Rust) | брикет (scene_hint тегами) |
| `vibe` — E01-E08 | LLM (валидация Rust) | брикет → глаза/выражение/поза |
| `lighting` — LP01-08 | LLM (валидация Rust) | брикет (recipe тегами; light_fn против №28) |
| `pose` — PLxx | LLM (валидация Rust по poses.json) | шапка + Spine + POS |
| `clothing` — merge с Дрессером | Rust (dresser.json: канал/категория/вещь/тон/состояния/подслой/NEG-веса) | брикет «ОДЕЖДА (№29)» → POS/NEG дословно |
| `character` — цвет волос, глаза, строение тела, метки | LLM (ОС — Canon из oc-canon.json дословно) | брикет → identity-блок POS |
| палитра, кости, стек, регистр, раса, K, closer, framing | Rust (детерминировано) | шапка/Spine/Stack/брикет |

Всё, что должно быть в итоговом рендере, назначается до писца — брикет вместо приказа.

## 4. ULTIMATE DICE в слотах

Порт `tools/dice.ts` (A5P6 §3, RAW-эра): кости **A** (порядок идентификации, 8), **B** (подача
одежды, 8), **C** (интеграция темы, 6), **D** (свет, 8), **E** (ритм, 6). Сигнатура
`A3·B5·C2·D7·E1` назначается каждому слоту детерминированно (mulberry32 от
`sha256(theme|slug|ars-noveau/v1|Pnn)`), уникальна в батче, печатается в Spine и брикете;
интерпретации граней — прямые инструкции писцу.

## 5. LLM-мост

`mini-services/llm-bridge` (bun, `127.0.0.1:3202`): `POST /v1/chat {system, user}` →
`z-ai-web-dev-sdk` (thinking off) → `{ok, content}`. Аутентификация: `x-bridge-key` =
командирский ключ (timing-safe по sha256, как в движках). Rust-твин вызывает мост
loopback-HTTP-клиентом (std::net, без новых зависимостей). Вся логика — в Rust; мост —
тупая труба к SDK, который живёт только в Node.

## 6. Роуты twin'а (:3201)

- `POST /v1/ars/new` {theme, ocThemes:[{name?,theme}]} → сессия (слаг T4-NN = max+1 по файл-истине)
- `POST /v1/ars/expand | assemble | scribe | gates | furnace` {id} → запуск стадии (worker-поток)
- `GET /v1/ars/sessions` · `GET /v1/ars/session/:id` → состояние сессии
- Сессии: `mini-services/t4-engine-rs/data/ars/<id>.json` (scratch-мир, прод не тронут)
- Гейт-прогоны ARS-батчей пишут `gate.run` в scratch-летопись (`record_gate_run`)
- FURNACE-вердикт пишет `experiment.logged` в scratch-цепь

## 7. FURNACE — формат репорта

Агент-оценщик (LLM через мост) смотрит, что налепили предыдущие инстанции: слот-карточки
(замысел), брикеты (заказ), готовый батч (исполнение), квитанции гейтов (машинный суд).
Ловит: недостатки гейтов, раскрытие темы по слотам, сделал ли писец свою работу — и если нет,
то почему. Репорт БЕЗ ПИЗДЕЖА: JSON-вердикт (`SHIP`/`HOLD`, score раскрытия, проблемы по
слотам с severity, сильные стороны, рекомендации) + обширный markdown-репорт в сессии.
FURNACE не переписывает батч — решение о сдаче остаётся за командиром (человеческий гейт).

## 8. Гарантии

- Прод-движок `:3200` и `t4.db` — RO для ARS; всё живёт в scratch-мире twin'а до явной сдачи.
- Грамматика батча — 1-в-1 с файл-истиной (`batch-md.ts`/`parse_batch`): 24 core (3 OC + 21 main)
  + ≤9 EXP; спред мейнов R+×14 · R×5 · PG-13×2; расовый каст 10/21; регистры третями.
- EXP-пары α/β/γ/δ + ι: план identical внутри пары, одна переменная (закон A/B).
- Законы в брикете: RAW+ №23 · №26 (название темы не в POS) · №27/№28 (канал-тон-состояние,
  bumps только на тёмном DRY) · §9 (салиент-цепь) · G20 (одна hard-заявка на R+) · NEG-гигиена №25.
- Онтология словарей: `thread4/specs/ars-ontology.json` (ENV/LP/E с light_fn — порт из
  ONTOLOGY.yaml + A2P13 LIGHTING PRESETS, чисто от вечных флоров).
