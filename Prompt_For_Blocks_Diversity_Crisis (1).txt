PROBLEM 1 — POSE & GAZE & CAMERA MONOTONY
═══════════════════════════════════════════════════════════════════════

OBSERVATION:
~80% of generated images show the character looking either left or
right, NOT at viewer. Cowboy shots are overrepresented. Even with
diverse settings and palettes, the silhouettes feel samey.

CURRENT RULES:
- 12 camera options (cowboy ≤8/batch, bust ≥3, other ≥10 total,
  min 6 distinct, no 3+ consecutive)
- 6 gaze directions (looking at viewer / past viewer / eyes down /
  eyes closed / looking at thread element / half-lidded)
- 20+ pose library entries (standing/seated/floor/yuri)
- Static Pose Audit: max 4 standing, min 7 non-standing
- Weight Center tags (anti-floating)
- Silhouette Vector (diagonal/S-curve/vertical/C-curve/twisted)
- Gaze × Thread Matrix assigns gaze based on thread type

USER ASKS FOR:
"A huge, colossally huge number of poses — left-directed, right-
directed, looking at middle, gaze from above to below, different
body orientations, conditional body parts — so that it never
repeats, or repeats in minimum amount."

QUESTIONS FOR YOU:
1. Why is the system producing 80% left/right gaze despite having
   6 gaze options? Is the Gaze × Thread Matrix (which assigns gaze
   based on thread type) the culprit? Most thread types map to
   "looking past viewer" or "looking at thread element" — both are
   averted gaze. Is this a design flaw?
2. How to expand pose vocabulary from 20 to 100+ without losing
   structural clarity? Should poses become compound tags? Should
   there be a "pose generator formula" rather than a fixed library?
3. Should camera caps be revised? Cowboy ≤8 is still high (8/21 =
   38%). Should we drop to ≤4? Add per-batch gaze quotas (e.g.,
   min 5 "looking at viewer")?
4. The user mentions "body parts" as a variety axis. Should we
   introduce "focal body part" as a parameter (hand / shoulder /
   back / foot / neck / hip)? How would this integrate with the
   35-slot tag order?
5. Is the problem really about POSE LIBRARY SIZE, or about
   COMBINATORIAL EXPLOITATION? 20 poses × 12 cameras × 6 gazes =
   1440 combinations per prompt. Why does output look samey? Is
   Block A defaulting to the same 5-6 comfortable combinations?

PROBLEM 2 — PALETTE NARROWNESS
═══════════════════════════════════════════════════════════════════════

OBSERVATION:
21 palettes with hair-eye bindings. User reports seeing "the same
green-haired girl" repeatedly — Hospital Ghost palette → pale green
hair, grey eyes — appears in multiple batches because its mood
(haunted, archival, marginal) fits many themes. Palette rotation
isn't sufficient.

CURRENT RULES:
- 21 palettes (Forge Ember, Hospital Ghost, Storm Surge, Feral Earth,
  Midnight Brass, Blood Stage, Ice Breath, Salt Sky, Candle Wax,
  Mud Field, Tattoo Ink, Rain Street, Lighthouse, Observatory,
  Garden Soil, Neon Veins, Wine Cellar, Dust Bloom, Obsidian Tide,
  Amber Ladder, Frost Glass)
- Palette-Hair Binding (each palette dictates 1 hair/eye pair)
- Palette as Character Arc (Act I cool, Act II fire, Act III warm)
- No adjacent duplicates, aim for 7+ distinct per batch
- Palette Echo (repetition requires 2+ changed params)

USER ASKS FOR:
"A huge number of palettes, so large that in 2-3 batches it will be
impossible to capture the number. Or — if we keep the count — make
palette selection so diverse that the same girl doesn't appear
repeatedly."

QUESTIONS FOR YOU:
1. Should we expand from 21 to 60+ palettes? Propose 15-20 NEW
   palettes that meaningfully differ from existing ones (not just
   renamed variations). For each: name, color formula, mood, hair
   binding.
2. Should we DECOUPLE hair/eye from palette? Currently each palette
   has ONE binding — this means 21 palettes = 21 character looks.
   If we allow 3-4 hair/eye variants per palette, we get 60-84
   looks. Trade-off: visual continuity within palette vs. variety.
3. Should we introduce "palette family" system — e.g., 5 variants
   of "warm-dark" palette (Wine Cellar, Blood Stage, Forge Ember,
   Candle Wax, Amber Ladder) that can substitute for each other?
4. The user mentions "the environment is changing, but this palette
   does not change." Is the problem the PALETTE COUNT or the
   PALETTE-HAIR BINDING making characters recognizable across
   batches?
5. Could we introduce HAIR/EYE LIBRARY independent of palette?
   30 hair colors × 20 eye colors = 600 combinations. Palette
   informs mood, hair-eye informs identity. Decouple completely.
