# README_MIGRATION — как распаковать чемодан и продолжить поток

Прочитай `MANIFEST.md` (опись и рецепты) — здесь только действия.
Всё проверено на сборке: сертификация перед tar зелёная + чемодан прошёл
песочный тест самодостаточности (распаковка в изолированный дом, весь
дым-тест повторён там — 5/5).

## 1. Требуемое дерево (контракт гейтов)

Органы находят файлы по ЖЁСТКИМ путям `/home/z/my-project/...`, окно ротации
выводят по номерам файлов `download/BATCH_N*.md`, а историю минтов сканируют
по всей плоской директории. Поэтому целевое дерево — точно такое же, как в
старом доме:

```
/home/z/my-project/
├── system/      — источник правды (20 файлов, из чемодана 1:1)
├── scripts/     — арсенал (25 файлов, из чемодана 1:1)
├── download/    — ПЛОСКО: 33 файла истории (18 батчей + 13 OC-ордеров +
│                  EXQ-01 + SP); зеркала .md регенерируются шагом 3
├── backup/      — worklog_archive_tasks_1-30.md ляжет сюда
└── worklog.md   — живой лог (STATE + Tasks 31–39)
```

Плоскость `download/` — не привычка, а контракт: pipeline и гейты ищут файлы
glob-ом (`BATCH_{N}_*.md`, `OC_ORDERS_*.md`) в корне `download/`, а спайн
сканирует ВСЮ историю (голова K-минта, X-фоссили). Подкаталоги гейты не читают.

## 2. Распаковка

```bash
tar -xzf CHEMODAN_THREAD_3.2-EXP_V21.tar.gz
cd CHEMODAN_THREAD_3.2-EXP_V21
./unpack.sh                     # цель по умолчанию: /home/z/my-project
./unpack.sh /другой/путь        # вариант Б — см. предупреждение ниже
./unpack.sh --force ...         # перезапись существующего system/
```

`unpack.sh` копирует файлы по дереву §1 и сразу гонит дым-тест (§4). Если дом
уже обитаем (system/ не пуст), скрипт спросит `--force`.

**Вариант Б (другой корень):** пути зашиты в ~10 инструментах
(`ROOT = Path("/home/z/my-project")` в spine.py / house_lint.py /
pipeline.py / rating_gate_lint.py / export_system_md.py и пер-батчевых).
Проще всего один sed по scripts/: `grep -rl /home/z/my-project scripts/ |
xargs sed -i 's#/home/z/my-project#/новый/путь#g'` — и повторить дым-тест §4.
(Именно так устроен песочный тест сборщика — приём проверен.)

## 3. После распаковки — регенерация зеркал

Зеркала (RULES.md, TRACKER.md, CARRIER_LIBRARY.md, README-индекс и т.д. в
download/) сознательно не везлись — их печатает экспорт из источника правды:

```bash
python3 scripts/export_system_md.py
```

## 4. Дым-тест чемодана (прогоняется unpack.sh; ожидаемые результаты)

```bash
python3 scripts/verify_system.py          # VERIFY PASS
python3 scripts/test_gate_v5.py           # ALL FOUR TESTS PASS
python3 scripts/spine.py selftest         # ALL SPINE SELFTESTS PASS
python3 scripts/house_lint.py --selftest  # ALL SELFTESTS PASS
python3 scripts/pipeline.py n29           # RESULT: 6/6 hard gates PASS
                                          # §62 FIRST-PASS [n29]: ретро-базлайн:
                                          # 60 ошибок · прогонов N · фикс-пассов 0
```

Известные нефатальные сигналы: `rhythm_lint` печатает `RESULT: FLAG` (клоузер-
триплеты, диагностика без `--strict` — прецедент N25); `freq` может упомянуть
субстрат-слова (не гейтуются); WARN'ы длины §60 у отдельных позиций — мягкие.
Каждый настоящий прогон house_lint дописывает рецепт в
`system/LINT_RECEIPTS.tsv` (append-only леджер §62) — рост счётчика «прогонов»
при том же sha ошибкой НЕ является; «фикс-пассов» растёт только при sha-дельте.

## 5. Как продолжить работу — ритуал V21 (контракт-фёрст, §62 FIRST-PASS)

Полная карта — `scripts/README.md`. Выжимка цикла:

1. `python3 scripts/spine.py compile n30` — спайн + КОНТРАКТ ПИСЦА
   (writer_contract в spine JSON: законы трёх органов, числа из их констант,
   ловушки T1–T14) — читать ДО письма прозы.
2. Правки законов (если есть) → `system/` → `python3 scripts/export_system_md.py`.
3. `python3 scripts/verify_system.py` — PASS обязателен.
4. Письмо и сборка ПРОТИВ контракта; дельты → блок в `house_configs.yaml`
   (`python3 scripts/house_lint.py --contract n30`).
5. `python3 scripts/house_lint.py --slug n30` — первый прогон: цель 0 ошибок.
6. `python3 scripts/pipeline.py n30` — все гейты разом + §62-строка.
7. Случился фикс-пасс → оплата §62(3): root-cause в ворклог + пункт контракта.
8. Сдано → ворклог (Task ID по порядку; следующая запись — Task 40+).

N30 — первый батч, градуируемый FIRST_RUN_CLEAN: «первый прогон линта = PASS» —
не цель-максимум, а определение сдачи.

## 6. Откуда тут что лежит (одним абзацем)

`download/` в чемодане — полный функциональный субстрат, а не выборка «на
память»: спайн выводит голову K-минта и X-фоссили по ВСЕЙ истории прозы, и
первая сборка с выборкой это доказала — песочный тест поймал молча заниженную
голову минта. Внутри субстрата поимённо выделены «самые удачные» (MANIFEST §3):
N18 (9.2/10 — высший whole-batch вердикт), N19 (рекорд фаворитов автора +
wet-sheer-дейтум), N29 (новый формат OC-merge, первый §61-прогон). Зеркала
download/ и одноразовые скрипты осознанно остались в старом доме: первые
регенерирует шаг 3, вторые помнит ворклог.
